# 「见一面」明星审美向量 + 深层理由方案（2026-11-18）

> 创始人两项拍板：① 放开「照片可进模型」，忠实复刻 tryDitto 的明星脸审美；② 把深层信号写进「为什么是你们俩」，让用户有信任理由（不能只是卡片选一样）。
> 本文是**设计方案**，动手前请过目；带「待确认」的是需要创始人定的点。

## 一、现状调研（代码取证，不是推测）

### 1. 明星照片采集链路已经存在
- DB：`photo` 表的 `kind IN ('profile','ideal')` —— `ideal` 就是「理想型/明星」照片位（V3 迁移）。
- 前端：`web/src/app/DeepInfoPage.tsx` 已有上传入口，文案「放一张明星或你很喜欢的 vibe 的照片」「只用于匹配，任何人都看不到」。
- 后端：`PhotoService.KINDS` 含 `ideal`。
- **结论**：采集全就绪，只差「把 ideal 照片编码成审美向量」这一步。

### 2. VLM 可用性已实测（关键验证）
- 网关（vveai，现有 embedding key）有视觉模型，实测可用：
  - `doubao-embedding-vision-251215`：走标准 `/v1/embeddings`，**图片直出 2048 维向量**。
  - 验证：同一张图余弦 0.9996（稳定），红图 vs 蓝图 0.7216（能区分）。
  - 还有 `InternVL3-38B/78B`（看图理解）备用。
- **视觉编码走现有网关、国内、Key 复用**，符合创始人选的 A 方案。

### 3. 向量库天然支持扩展
- Qdrant collection 用 named vectors，现有 `taste`/`persona` 两个（1024 维 Cosine）。
- 加第三个 `aesthetic`（2048 维）**无需重建 collection 结构**，RRF 融合加一路即可。

### 4. 深层信号已在库，只是没喂文案
- `AiJudge` 精排时输出四维（values/chemistry/vibe/feasible）+ topics + reason_text + 3 轮分身对话，落 `recall_candidate.sim_report`。
- 时序：SOLVE（写 sim_report）→ COPY（写文案），文案阶段能读到。
- **锁死「标签重合」的根因**：`CopyValidator` 要求理由 cites 只能取双方共同问卷项；`AiCopyGenerator` 提示词只喂 ProfileFacts 白名单 + 共同项。深层信号根本不在允许输入里。

## 二、深层理由方案（已实现代码 + 单测，待补演示数据）

### 已落地（本轮）
- 新增 `ResonanceHint`：从裁判 dims/confidence 提炼**固定安全词表**标签（聊得来/节奏合拍/想法相近），只信高置信、非降级结果；**绝不携带 reason_text / 分身对话原文**（防 PII 与编造）。
- `CopyContext` 增加 resonance 字段：`present()` 时把 `resonance` 作为双方合法共享 cites，标签进可用词表。
- `AiCopyGenerator` 提示词：有共鸣观察时允许写 1 条跨表面理由（cites=resonance），并限定用词。
- `MatchDb.resonance(low,high)`：从 sim_report 只读结构化 dims 转成受控标签。
- `MatchCopyWriter`：写文案前注入共鸣信号。
- 单测 `ResonanceReasonTest` 4/4 通过（含「无信号时 resonance cite 被拒」防凭空编造）。

### 效果与边界
- **有精排共鸣信号时**：理由能写「你们的聊天节奏意外合拍」这类跨表面判断。
- **无信号/降级时**：自动退回标签理由，零回归、零编造。
- **线上暂看不到效果**：当前 demo 账号是预置模板文案，且 demo 用户没有 `user_taste`、没有 sim_report。真实周批 pairs=0（同校硬约束 + 跨校）。要让创始人在线上看到深层理由，需补一步「给演示配对跑画像提取 + 精排 + AI 文案」（见第四节待办）。

## 三、明星审美向量方案（待创始人过目后动手）

### 数据流
1. **采集**：用户上传 ideal 照片（前端已有）→ PhotoService 存 `kind=ideal`。
2. **编码**：新增 `VisionEmbeddingService`（实现 `doubao-embedding-vision-251215`，2048 维，闲时批量）→ 把每张 ideal 照片编成向量，多张取均值。
3. **存储**：Qdrant 加 `aesthetic` named vector（2048 维）；PG 加字段记录审美向量版本/同步状态。
4. **召回**：新增第六路 `R6_AESTHETIC`——用「我方 ideal 审美向量」去查「对方 profile 照片的视觉特征向量」的近似。
   - 需要两侧向量：需求侧（我的 ideal 照片→我喜欢的长相）、供给侧（我自己的 profile 照片→我的视觉特征）。**这正是 tryDitto 的双侧审美**。
5. **融合**：R6 纳入 RRF，权重待调（建议先 0.5 试跑，看独占单路占比闸门）。
6. **合规边界**：
   - 照片只发国内网关（vveai），不出境；
   - 只在匹配阶段用，不展示、不进文案、不落明文日志；
   - 前端原有「只用于匹配，任何人看不到」文案与之一致，叙事自洽；
   - 需更新技术方案 §8.1：从「照片不发任何模型」改为「照片仅发国内合规视觉模型用于审美向量，不进文本提示词、不展示」。

### 成本
- doubao-embedding-vision 按图计费；一周一次批量、用户量小，可放夜间闲时（已配 DeepSeek 闲时策略同理）。
- 待确认：是否接受为每张 ideal/profile 照片调用视觉编码（约 2 次/用户/周）。
