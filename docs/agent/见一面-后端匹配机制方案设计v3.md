# 「见一面」后端匹配机制方案设计 v3（上线前全量版）

> **本文推翻 v2 的阶段计划，以本文为准。** v2 的 DDL / API 契约 / 算法 / prompt 仍有效，但需按本文第三、四节修订。
> 修订原因：v2 提出"阶段一零 LLM、先推广、第 4 周解锁精排"——这是错的。面向 C 端学生用户的产品，功能必须在推广前完整齐备并用合成反馈把整个生命周期跑通，不能让真实用户替我们试错。
> 配套：`见一面-召回策略规格.md`、`见一面-合成反馈仿真与上线前测试方案.md`、`见一面-matching-schema.sql`（v3 修订）、`见一面-匹配系统-Prompt模板.md`
> 日期：2026-11-15

## 一、先认错：v2 错在哪

| v2 的说法 | 问题 |
|---|---|
| "阶段一（1-3 周）零 LLM，先跑通交付链路" | 等于把没有学习能力的产品推给学生。第一周的错配就是真实伤害，不可逆，且这批用户的信任一次性损失 |
| "第 4 周解锁 Agent 精排" | 上线后再加核心功能，等于 A/B 测试的对照组是真实用户。C 端不允许 |
| "等有真实反馈再校准" | 完全可以、且必须用**合成反馈 + 隐藏真值**把学习闭环跑通并验证"越学越准"，再接真实数据 |
| "pgvector 省一个组件" | 致命轻率。pgvector HNSW 是 post-filter：过滤选择性 10% 时 Recall@10 = 0.398，1% 时 0.039，0.1% 时 0.003，且**静默返回不足结果不报错**。我们的硬过滤（同校+性别+等时圈+dealbreaker）选择性正好在 1-10%，候选池会被悄悄抽空 |

**结论：召回是命门，反馈闭环是产品的灵魂，两者都必须在上线前打磨到指标达标，不是上线后长出来。**

## 二、修正后的铁律与阶段模型

### 铁律

1. **功能全量先行**：注册到下一周期的完整生命周期、Agent 精排、反馈学习、召回融合、安全体系，一行不少地上线前完成
2. **先用合成数据把闭环跑穿**：500-2000 个合成学生 × 8-12 个虚拟周期，验证"越匹配越准"，对抗与边界用例全过
3. **真实用户只用于验证，不用于试错**：小灰度时所有功能已全开，合成回放继续并行作为对照
4. **任何核心能力都不许"先上线再补"**：推广只是放大流量，不是开发阶段

### 阶段模型（与 v2 完全不同）

| 阶段 | 内容 | 出口条件 |
|---|---|---|
| **A 功能全量开发** | 全部功能、全部安全能力、全部降级与监控，无裁剪 | 代码完成 + 单元/集成测试通过 |
| **B 合成仿真打磨（上线前，重点）** | 合成反馈回放召回策略、裁判、配对、画像学习；对抗与边界用例；压测；成本演练 | 第五节 Go/No-Go 全表达标 |
| **C 小灰度（全功能）** | 单校白名单 50-200 名真实用户，全功能开启；合成回放并行 | 真实指标与仿真预测偏差在容忍带内，零 P0 事故 |
| **D 推广** | 单校全量 → 大学城 → 多校 | 按池子健康度滚动 |

**阶段 B 是本项目最重的阶段，不是可压缩的过渡期。** 详见配套《合成反馈仿真与上线前测试方案》。

## 三、架构修订（v2 第三节作废）

```
PostgreSQL 16       业务主库：用户/偏好/配对/反馈/审计/同意记录（不再存向量）
Qdrant              主召回库：多向量 + payload 标量过滤 + filterable HNSW + 稀疏混合
pgvector(影子)      仅离线精确对照：算 Recall@K 的 ground truth，不服务在线
Redis               池快照 / 幂等锁 / 批次状态 / 触达重试队列 / 熔断计数
XXL-JOB             周批调度 + 仿真回放调度（两套隔离的 job）
对象存储            照片(审核后)/海报，加密 + 生命周期策略
仿真沙箱            sim schema 独立，同一套业务代码 + 数据源开关，绝不污染生产
```

**选 Qdrant 而非 Milvus 的理由**（有据可依，不是拍脑袋）：过滤 1% 场景 Qdrant Cloud 实测 recall=1.0，filterable HNSW 把 payload 索引并入图遍历，从根本上避开 post-filter 塌陷；单二进制/单 Docker，运维面小；原生 named vectors（多向量）、稀疏 BM25、服务端 RRF 融合、Java SDK 齐备。Milvus 在千万级以上、需要 K8s 分片时再迁移，接口层用 `RecallService` 隔离，换引擎不改业务代码。

**pgvector 不删，改作影子**：每次线上召回同步跑一次精确检索（可在离线/低峰），持续产出"ANN  Recall@K vs 精确结果"的监控曲线。召回质量变成可观测指标，而不是信仰。

### 新增组件契约

| 组件 | 职责 | 关键约束 |
|---|---|---|
| `RecallService` | 五路召回 + RRF 融合 + 保底 | 每路可独立开关/配权；返回必须带 `source` 便于归因 |
| `VectorSyncService` | PG → Qdrant 双写 + 版本 | embedding 模型升级走双写 + 影子索引 + 回放对比后切流 |
| `SimEnvironment` | 合成用户/反馈 Oracle/回放驱动 | 与生产代码同仓同逻辑，`is_synthetic` 隔离 |
| `EvalJob` | 每周期算 Recall@K / regret / taste_recovery | 仿真与灰度共用一套指标实现 |
| `SafetyGuard` | 举报拉黑/签到/求助/内容审核 | 拉黑 <1s 生效，且向量库同步删除 |

## 四、完整生命周期（上线前必须每个节点都测通）

| # | 节点 | 异常分支（必须实现，不是"以后再说"） |
|---|---|---|
| 1 | 手机号登录 | 验证码重发限流、错 5 次锁定、协议未勾选拦截、注销用户禁止复活同号 |
| 2 | 18+ 与学籍双校验 | 17 岁拦截、edu 邮箱格式与归属校验、学籍核验失败可申诉复核 |
| 3 | 人脸核验 | 只存结果不存原图、失败重试上限、失败用户不进池 |
| 4 | 照片上传 | 机审 + 人审兜底、不足 2 张不进池、审核中状态显式、驳回可重传 |
| 5 | 服务端驱动问卷 | 断点续填、任意步退出重进、跨设备进度一致、答案逐题落库 |
| 6 | 偏好提交 | 周二 23:59 截止、截止后 423、截止前 20:00 提醒、修改留痕 |
| 7 | 周批：硬过滤 | 等时圈无重合、池子枯竭、封禁/拉黑/已配过排除、注销后不得召回 |
| 8 | 周批：多路召回 | 任一路失败降级、召回不足保底、影子对照算 Recall@K |
| 9 | 周批：粗排 + Agent 精排 | LLM 超时/非法 JSON/全挂/成本熔断四级降级 |
| 10 | 周批：全池配对 | 撞车、饥饿优先、低于阈值不推、人工干预留审计 |
| 11 | 周三 19:00 交付 | 准时 ±1 分钟、解释海报生成失败兜底、触达失败 3 次重试 + 短信兜底、退订尊重 |
| 12 | accept / refuse | 单方拒绝不暴露给对方、双方接受才进排期、refuse 必收 reason_tag |
| 13 | 排期与场地 | 时间槽无交集改下周、场地满员改备选、双方确认后才锁定 |
| 14 | 赴约前 | 前 2h 提醒、天气/场地临时变更通知、取消有申诉通道 |
| 15 | 到场签到 | 双方扫码签到、单方 15 分钟未到自动取消并安抚、爽约计分 |
| 16 | 约会中安全 | 校内公共场地白名单、时长上限 2h、超时关怀提醒、一键求助、紧急联系人 |
| 17 | 反馈三问 | 24h 内采集、超时补提醒、无反馈不阻塞下一周期但标记稀疏 |
| 18 | 画像更新 | 版本化、每周 ≤1 次、单次调 1 权重、失败保留旧版 |
| 19 | 下一周期 | pair 永久记忆生效、饥饿优先、长尾曝光保底 |
| 20 | 注销 / 数据导出 | 向量库/对象存储/日志关联一并清理，清理后验证不得召回 |

## 五、上线闸门 Go/No-Go（全部达标才允许进 C 阶段）

| 类别 | 检查项 | 阈值 |
|---|---|---|
| 闭环 | 合成回放连续周期数 | ≥12 周期，全生命周期零中断 |
| 学习 | 学习曲线 | regret 单调下降 ≥8/12 周期；末周期 top1 落在真实合拍 top10% 的比例 ≥60% |
| 学习 | 口味还原度 taste_recovery | ≥0.70（独立评判模型打分） |
| 学习 | 冷启动基线 | 第 1 周期（零反馈）top1 命中率 ≥35% |
| 召回 | Recall@50 对照精确检索 | ≥0.95；**过滤选择性 1% 桶 ≥0.90** |
| 召回 | 五路召回归因 | 每路均有非零贡献，单路占比 ≤60%（防单点依赖） |
| 召回 | 长尾曝光 | 最不活跃 20% 用户获得曝光比例 ≥其人数占比的 80% |
| 安全 | pair 重复推送率 | 0（含拉黑/拒绝/注销后） |
| 安全 | 对抗用例 | P0 用例通过率 100%，P1 ≥95% |
| 安全 | 举报拉黑生效 | <1s，双向解除，向量库同步 |
| 安全 | 注销清理 | 向量库/对象存储/日志验证通过，且回放验证不得召回 |
| 安全 | 18+ 拦截 / 内容安全 | 样例集 100% |
| 工程 | 周三交付准时率 | 100%（±1 分钟），P99 ≤60s |
| 工程 | 降级演练 | LLM 单候选失败 / 全挂 / 成本熔断 / Qdrant 不可用 四种全部通过 |
| 工程 | 压测 | 峰值 QPS 下池快照与召回 P99 达标，无雪崩 |
| 成本 | 单周期单校成本 | ≤预算上限，熔断演练生效 |
| 合规 | 备案 / 等保 / 同意项 | 材料就绪，PIPL 分项同意与导出/注销接口可用 |
| 运营 | 值班与回滚 | 回滚演练通过，周三晚有人值守 |

**任何一项未达标 → 不进灰度，继续在阶段 B 打磨。** 这是硬闸门，不是建议。

## 六、面向 C 端学生用户的细节清单（我作为总操刀手逐项兜住）

### 6.1 人身安全（最高优先级，学生线下见面是这个产品最大风险）
- 场地只能是**审核过的校内公共地点**白名单，禁止用户自定义私人地点/宿舍/校外住址
- 双方到场签到；单方 15 分钟未到自动取消、通知另一方并安排安抚，不让用户干等
- 约会时长上限 2 小时，超时触发关怀提醒；一键求助直连平台值班 + 校园保卫（逐校配置）
- 紧急联系人可选填；求助记录留档可追溯
- 夜间不安排（结束时间硬上限按学校作息配置）；22:00-08:00 不推非紧急通知
- 照片/人脸/资料只在**配对成功后双方互见**，未配对用户之间完全不可见、不可搜索

### 6.2 隐私与体面
- 位置只呈现等时圈/大致区域，绝不暴露精确坐标、常驻点、实时位置
- 拒绝方的原因**永不展示给被拒绝方**；界面不出现"你被拒绝""不匹配"字样，用"本周未安排"统一话术
- 不显示在线状态、最后活跃、匹配分数、人气排行
- 联系方式在双方确认赴约后才通过短信管家交换，不直接暴露手机号
- 画像文本（`taste_text`）属于用户画像，必须可导出、可删除；注销时向量库同步删除

### 6.3 公平与非歧视
- 禁止对外貌打分、禁止推断敏感属性（政治/宗教/健康/性取向）、禁止用照片做吸引力评分
- 长尾用户曝光保底：新用户与连续未匹配用户有独立召回配额，防止热门用户垄断
- 每周跑一次公平审计：按性别/校区/身高区间/活跃度分组看曝光率与赴约率，异常报警
- 算法备案材料需说明人工干预机制与公平性措施，审计表已备

### 6.4 心理与体验
- 无匹配周必须有安抚文案 + 明确"下周优先"，不能静默空发
- 连续 2 周期未匹配自动进入饥饿优先队列并给一次人工复核机会
- 拒绝后不追问、不反复提醒；反馈问卷 3 问以内，可跳过
- 爽约有惩罚（暂停/支付分）但必须有申诉通道，避免误伤

### 6.5 触达与时间
- 微信服务号模板消息为主、短信兜底，失败 3 次重试 + 触达日志
- 周二 20:00 截止提醒、周三 19:00 准时交付（Asia/Shanghai，±1 分钟）
- 退订/免打扰立即生效；通知文案不做焦虑营销、不用"再不…就…"

### 6.6 内容安全
- 所有自由文本（问卷/反馈/原话）入 LLM 前过滤 PII 并过内容审核
- LLM 模拟对话、海报文案输出双向审核；敏感词、越界人设、不当内容一律拦截
- 照片机审 + 人审兜底，审核不通过不进池

### 6.7 工程兜底
- 幂等（cycle+stage 唯一键）、断点重跑、Redis 分布式锁
- 四级降级：单候选失败 → 粗排兜底；全批失败率>20% → 报警+人工确认；Qdrant 不可用 → 结构化召回+标签召回；周三 18:00 未到 DELIVERING → 自动降级粗排交付，绝不空发
- 成本熔断按周期累计金额，触发即停精排
- 全链路监控：召回质量（影子对照）、反馈率、赴约率、投诉率、准时率、降级次数、成本
- 灰度开关按学校/用户粒度，一键回滚到上一周期结果

### 6.8 合规
- 算法备案（beian.cac.gov.cn 新系统）、AIGC 登记（用已备案国产模型）、B25、等保三级、公安联网备案、安全评估
- PIPL 分项单独同意（问卷/人脸/位置/照片/画像各自勾选），未成年人 18+ 硬拦截
- 收费前资质到位；演示数据与真实数据严格隔离标注

## 七、我的决定（不再挂"待拍板"，有异议直接指出）

| 事项 | 决定 | 理由 |
|---|---|---|
| 阶段模型 | 功能全量 → 合成仿真 → 小灰度（全功能）→ 推广 | C 端不允许用真实用户试错 |
| 反馈来源 | 上线前用**合成反馈 + 隐藏真值**，上线后真实反馈叠加 | 学习闭环可离线验证"越学越准"，不需要拿学生练手 |
| 向量库 | **Qdrant 主召回 + pgvector 影子精确对照** | 过滤选择性 1-10% 场景 post-filter 会静默摧毁召回；filterable HNSW + 可观测 Recall@K 是必须的 |
| 召回策略 | 五路召回 + RRF 融合 + 保底，路路可归因 | 单一路召回无法覆盖冷启动、长尾、审美、结构化条件 |
| 精排 | 上线即开（D1 双分身互约），但带完整降级链 | 不能后补；降级保证任何故障都不空发周三 |
| 模型 | 模拟便宜档、裁判/画像强档，走配置中心 | 成本可控且裁判可单独升级 |
| 上线闸门 | 第五节全表硬门槛，未达标不灰度 | 把"谨小慎微"变成可验收的数字 |
