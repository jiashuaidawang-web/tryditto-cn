# 自适应情景采集引擎设计（2026-11-18，治本工程）

> 创始人定调：**先治本，搭底层基础设施，不着急看效果**。核心目标——让分身用主人的语气说话/提问，攒下"本人性格 + 说话方式"这份**资产**。
> 创始人原始设计（已逐条落实）：LLM 动态出独一无二的题 → 给几个方向、按"认为用户最可能选的"排 A/B/C → 用户选（或自定义输入）→ 据实生成下一题 → 可随时停 → 基于已答推断性格。

## 一、设计灵魂：预测—验证闭环

普通问卷只是"收集答案"；这套引擎把每次答题变成一次**模型对人的验证**：

1. LLM 出题时，必须先赌"这个人最可能选哪个"，把最可能的放 **A 位**（predict_rank=1），依次排序；
2. 用户**实际选了什么** vs **系统预测他选什么**，差距就是**校准信号**（`predict_hit`）；
3. 下一题把这个"看错/看对"喂回去，LLM 修正对人的猜测，题目越来越贴合真人；
4. 连续命中（系统已能稳定预测此人）或用户主动停 → 基于全部作答推断人格 + 语气。

**命中率（calibration）= 系统对这个人理解得准不准的代理指标**，也是后续"越匹配越准"的可信地基。

## 二、已落地的数据模型（V12）

| 表 | 作用 |
|---|---|
| `voice_session` | 一次采集会话（active/completed/abandoned），步数、起止时间 |
| `voice_question` | LLM 生成的题 + 选项 JSON（含每项的 `predict_rank` 预测排序） |
| `voice_answer` | 用户作答：选中的 key / 加密的自定义原话 / `predict_hit` 校准信号 / trait 信号 |
| `voice_sample` | **语气样本资产**：用户本人原话（自定义输入），加密存储，供分身学习 |
| `voice_profile` | **人格推断资产**：traits + 语气风格 + 命中率，版本化、只激活最新一版 |

合规：只存用户**本人自愿**的情景作答；自定义文本加密；不接微信/聊天记录/任何第三方数据；前端拿到的选项**不含 predict_rank**（防被刷）。

## 三、已落地的代码

| 文件 | 职责 |
|---|---|
| `domain/voice/VoiceModels.java` | 纯函数：选项/题/作答结果、`evaluate`（算校准）、`calibrationRate`、`converged`（连续命中收敛） |
| `voice/ScenarioPrompts.java` | 出题提示词（强制 predict_rank 排序）+ 严格解析（排序必须是排列、PII 判废、格式容错） |
| `voice/ProfileInferencePrompts.java` | 会话结束推断人格 + 语气风格 + 严格解析 |
| `voice/VoiceSessionService.java` | 引擎主体：start / answer / stop / profile；LLM 全挂时走固定兜底题库 |
| `voice/VoiceController.java` | 4 个 API：`POST /api/voice/start`、`/answer/{questionId}`、`/stop/{sessionId}`、`GET /profile` |

**关键参数**：最多 12 题；至少答 3 题、连续 3 次命中预测第一 → 自动收敛；用户可随时 stop。

## 四、API 流程（前端接入契约）

```
POST /api/voice/start → {sessionId, questionId, step, scenario, options:[{key,text}]}
POST /api/voice/answer/{questionId}  body:{chosenKey} 或 {customText}
   → {sessionId, step, predictHit, calibration, done,
      profile?}  // done=true 时带人格结论
   → done=false 时带 question:{questionId, step, scenario, options}
POST /api/voice/stop/{sessionId} → 基于已答推断，返回 profile
GET  /api/voice/profile → 当前生效的人格资产
```

## 五、验收（已实测）

- `VoiceModelsTest` 5/5：校准信号、命中率、收敛判断（自定义输入打断收敛）。
- `ScenarioPromptsTest` 6/6：预测排序排列校验、PII 拦截、格式容错、提示词含"最可能"。
- `VoiceSessionIT` 1/1（真 PG16）：start→答题命中→自定义输入→stop→人格资产入库→profile 查询全通。
- 端到端实测输出：`calibration=1.0`，人格资产（traits/summary/voice_style）成功落库。
  （集成环境 LLM 是 mock，出题/推断走兜底；真实模型下的高质量出题与推断需配 live key 验证。）

## 六、治本最后一公里：接回分身（2026-11-18 已完成）

- `VoiceAssetService.voiceHint(userId)`：读 `voice_profile.voice_style` + 最近 3 条 `voice_sample` 原话，脱敏（邮箱/手机/密钥/链接）、单条截 80 字、总量截 320 字；无资产返回空串。
- `AgentRerankService.loadPersonas()`：把 voiceHint 拼进 `persona[0]`（`【语气参考】...`），分身模拟从此用本人语气说话/提问；无资产时 persona 逐字不变（零回归）。
- `AiJudge.simulateSystem()` 新增铁律 1b：A/B 必须严格按各自【语气参考】说话（句长、用词、直接/委婉、爱不爱开玩笑），优先级高于性格描述。
- 端到端实测：`voiceHint=说话风格：...。本人常这样表达：我一般会直接说，别绕弯子，我这人就这样` —— 用户原话真正成为分身语气锚点。

## 七、采集页闭环（2026-11-18）

1. **前端已接上**：入驻最后一页进入 `/voice`（选填，可「先不答了」）。「我的」里也有「说话方式」入口。选题或自定义原话（最多 80 字，和分身读到的长度一致）；刷新会续上未答的当前题，不会另出一题。
2. **资产已经进分身**：答完或主动停止后，`voice_profile` / `voice_sample` 由 `VoiceAssetService` 注入精排分身提示词。页面上会把记下的语气原样展示给本人。
3. **还没做**：真实模型下的出题质量和语气还原度；放大模拟次数。NO-GO 不变。

> 本引擎是底座，不改变现有配对主流程；NO-GO 判定在"越匹配越准"被证明前不变。
