# 分身 Agent 保真度决策（2026-11-18）

> 创始人核心洞察：**重点不是把模拟跑几次，而是分身能不能用主人的语气说话/提问**。一个不像主人的分身，跑 1000 次只是把失真放大。
> 这是 NO-GO「越匹配越准没证明」的深层原因：模拟的化学反应建立在 AI 脑补的分身上。

## 一、现状（代码取证）

| 环节 | 现在怎么做的 | 问题 |
|---|---|---|
| 分身人设来源 | `persona_text` = TasteWriter 根据用户填的 30 个问卷字段（喜欢什么音乐/最近读什么书…）写的 120 字气质描述 | 是 AI 想象的"气质"，不是本人真实说话方式 |
| 分身对话 | AgentRerankService 拿这段描述，让 LLM 现场编 3 轮对话 | 语气是模型脑补的，双方"提问/回答"都不像本人 |
| 裁判打分 | 基于这段失真的对话评 chemistry | 打分建立在失真分身上 → 模拟不出真实化学反应 |

**结论**：瓶颈不在模拟次数，在分身保真度（像不像本人）。

## 二、关于「微信聊天记录」——不能接，三个硬理由

1. **第三方隐私**：聊天记录里大量是对方的信息，你无权把别人的话喂给我们的模型。
2. **微信不允许**：爬取微信聊天记录违反微信服务条款，技术上也不开放；做这件事会把产品置于法律与封号风险中。
3. **触碰自家红线**：技术方案 §8.1 与 TasteFacts 白名单明确禁止 PII（真实姓名、联系方式、聊天原文）进模型——这是当初为保护 C 端学生定的，不能为效果破例到这种程度。

> 创始人的目标（分身像本人）是对的，但聊天记录这条路代价不可逆。下面给能落地的替代。

## 三、三条合规替代路径（按推荐排序）

### 方案 A（推荐）：入驻时让用户自己给「语气样本」
- 加 3 道开放式情境题，保留**本人原话**：
  - "你会怎么约一个刚认识的人喝咖啡？"
  - "如果对方说的你不太认同，你会怎么回？"
  - "第一次见面冷场了，你会怎么开口？"
- 这些原话经脱敏后存入 `voice_samples`，作为分身系统提示词的一部分——分身照着本人的说法风格说话。
- 优点：本人自愿提供、可控可删、合规、最能还原语气。
- 缺点：多 3 道题，入驻流失可能略升（可用"选填"缓解）。

### 方案 B：复用已有自由文本（零新增采集）
- 用户已经填过 `firstMessage`（第一句话怎么开场）、`datingHelp`（约会期待）等自由文本，且已在脱敏白名单内。
- 把这些原话作为语气锚点喂给分身，不引入任何新数据源。
- 优点：零隐私增量、零流程改动、马上能做。
- 缺点：样本少，语气还原度不如 A。

### 方案 C：反馈原话反哺（越用越像）
- 见面后用户写的真实反馈原话，经本人同意后校准其分身语气。
- 与反馈闭环天然结合，是"越用越像本人"的正循环。
- 优点：真实、持续变好。
- 缺点：要等真实反馈（现在 NO-GO 没真实用户），且需明确授权。

## 四、我的建议

1. **先做 B**（零成本、马上能做）：把已有自由文本接进分身提示词，先让分身"有一点本人的味道"。
2. **再做 A**（治本）：加 3 道语气样本题，选填，让愿意的用户分身高度还原。
3. **C 接反馈闭环**：等真实用户后开启。
4. **跑次数**放在最后——分身像了之后，加大模拟次数/场景才有意义。

## 五、需要创始人拍板

1. 是否同意"微信聊天记录不接"这个红线判断？
2. 方案 A 的 3 道语气样本题，是必填还是选填？（我建议选填，避免流失）
3. 是否按 B→A→C 的顺序推进？

> 这条链路直接决定"模拟化学反应"是否可信，是让匹配真正变准的根。NO-GO 判定在"越匹配越准"被证明前不变。
