# 「见一面」合成反馈仿真与上线前测试方案

> 配套：`见一面-后端匹配机制方案设计v3.md`
> 回答的问题：**没有真实反馈，怎么在上线前把学习闭环跑通并证明"越匹配越准"？**
> 答案：造一批带**隐藏真值**的合成学生，让一个独立的反馈 Oracle 按真值给出反馈，跑 12 个完整虚拟周期，用可计算的指标验证系统确实学会了用户的真实审美。
> 日期：2026-11-15

---

## 一、为什么必须模拟反馈（直接回应"来得及吗"）

v2 把"等真实反馈"当成解锁条件，逻辑是反的：

- 学习闭环是这个产品**最核心、最容易出错**的部分（画像漂移、单次差评洗画像、口是心非、拒绝原因误读、裁判自说自话）。它恰恰是最不能拿真实学生练手的模块
- 真实反馈一周只有一批、不可逆、样本稀疏且带情绪噪声；上线后才发现"学反了"，伤害已经发生
- 合成反馈可以**无限快、可复现、有标准答案**：隐藏真值让我们第一次能回答"系统到底学对了没有"，这是真实数据永远给不了的

**所以：不是来不及，而是必须先在仿真里把闭环跑穿、把指标打到达标，才允许接入真实用户。** 阶段 B 是本项目的质量闸门，不是过渡期。

## 二、仿真沙箱架构

```
sim_* schema（独立库/schema，绝不污染生产）
  sim_user / sim_hidden_truth / sim_run / sim_cycle_metric / sim_feedback_log / sim_case_result

同一套生产代码（不写"仿真专用简化版"）
  └─ 数据源开关 DataSourceRouter：真实 / 合成 / 混合
  └─ SimClock：虚拟时间，一个周期压缩到分钟级
  └─ FeedbackOracle：替代真人提交 POST /api/feedback
  └─ SimDriver：驱动 12 周期回放 + 对抗用例注入

隔离要求
  - is_synthetic 标记贯穿 PG / Qdrant / 对象存储 / 日志
  - 合成向量写独立 collection match_user_sim_v1
  - 仿真产生的通知、海报、触达一律进 mock sink，不得真实发送
  - 仿真 job 与生产 job 用不同 XXL-JOB 分组，禁止误触生产周期
```

**关键原则：仿真跑的是生产代码本身。** 写一套"仿真简化逻辑"等于什么都没验证。

## 三、合成用户生成

### 3.1 规模与分布

| 项 | 设定 |
|---|---|
| 规模 | 单校 500 / 2000 两组，另跑 100 人小池与 10000 人多校组 |
| 性别比 | 覆盖 1:1、4:6、3:7 三种（真实校园常见失衡，配对算法必须扛得住） |
| 长尾覆盖（必须显式构造） | 极内向、少数取向、身高两端、异地实习、无 crush 照片、照片仅 2 张、非典型爱好、连续低活跃、大龄研究生、不填身高 |
| 口是心非组 | **≥20% 用户**的"嘴上条件"与隐藏真值故意不一致（嘴上说身高/学历重要，真实反馈全在夸幽默感与节奏感）——这是验证"学到真实审美"的关键样本 |
| 脏数据 | 自由文本含错别字、矛盾表述、极短"还行吧"、情绪化差评、空白反馈 |
| 生命周期事件 | 注销、拉黑、爽约、暂停、照片被驳回、人脸失败、学籍申诉 |

### 3.2 隐藏真值 `hidden_taste`（系统全程不可见）

每个合成用户生成一个 10 维权重向量（0-1），维度示例：

```
humor 幽默感 / adventure 冒险性 / expressiveness 表达欲 / calm 安静度
schedule 作息契合 / ambition 学业投入 / spending 消费观 / warmth 情绪温度
height_sensitivity 身高敏感度 / look_weight 外貌权重
```

外加 `crush_vector`（审美）、`dealbreakers_true`（真实红线）。系统只能看到问卷答案、照片、模拟对话与反馈文本，**永远看不到这张表**。

### 3.3 兼容度函数 `true_score(a,b)`（Oracle 的核心）

不能是简单线性内积——否则系统用线性模型就能猜中，测不出"人格共振"。设计为：

```
base   = Σ_i  w_i · f(a_i, b_i)             # 部分维度互补、部分相似
inter  = humor_a × expressiveness_b
       + adventure_a × adventure_b
       + calm_a × calm_b                     # 交互项：跨表面共鸣
gate   = 命中任一真实 dealbreaker → 0        # 硬否决
noise  = N(0, σ)                            # 人类主观噪声
true_score = gate × (0.6·base + 0.4·inter + noise)   # 归一化到 0-100
```

交互项是关键：它模拟了 Ditto 的主张（攀岩男 × 街潮女，爱好零交集但内核同为冒险型）。**只用标签重合度的系统在这批样本上必然学不动**，指标会立刻暴露。

### 3.4 合成用户生成 Prompt（可直接用）

```
SYSTEM:
你在为一个校园约会产品的仿真测试生成合成学生档案。输出严格 JSON，不要 markdown 代码块。
要求：档案要像真实中国大学生，不要模板化；爱好要具体到细节（"周二晚上在宿舍煮意面"而不是"喜欢做饭"）；
不要生成任何真实姓名、手机号、身份证号、真实学校全称以外的可识别信息。

输出：
{
 "stated_profile": {"问卷答案": "...", "嘴上强调的条件": "...", "爱好细节": "...", "MBTI": "..."},
 "hidden_taste": {"humor":0.0, ..., "height_sensitivity":0.0},
 "crush_description": "……",
 "dealbreakers_true": [],
 "persona_style": "说话风格：……",
 "is_two_faced": false       ← 20% 置 true，嘴上条件与 hidden_taste 故意冲突
}

USER:
【批次】{{batch_id}} 【序号】{{n}}
【需要覆盖的长尾类型】{{long_tail_tag}}
【性别/年级/校区】{{demographic}}
【is_two_faced】{{true/false}}
```

生成后校验：JSON schema、`hidden_taste` 10 维齐全、`is_two_faced=true` 时显性条件与真值确实冲突（自动断言）。

## 四、反馈 Oracle（模拟真人反馈）

### 4.1 结构化反馈

| 字段 | 生成规则 |
|---|---|
| `meet_again` | `Bernoulli(sigmoid((true_score − 60)/10))` |
| `accuracy` | `round(true_score/20)` 夹到 1-5，加 ±1 噪声 |
| `reason_tag` | 从真值里取贡献最大/最小的维度映射（如"没话题"← expressiveness 低、"条件都对但没感觉"← 交互项低） |
| `free_text` | LLM 按真值写一句口语化中文反馈（模板见 4.2），带口是心非/矛盾/极短/情绪化噪声 |

### 4.2 反馈文本生成 Prompt

```
SYSTEM:
你在扮演刚结束一次校园咖啡约会的学生，写一句真实反馈。
规则：
1. 只根据给定的"真实感受"写，不要替系统解释、不要提算法或评分。
2. 口语化、可带错别字、可以很短；20% 的情况只写"还行吧""一般"这类无信息量回复。
3. 若标记 ambivalent，写一句自相矛盾的话（"人挺好的，但就是没啥感觉，说不上来哪不对"）。
4. 若标记 emotional，允许情绪化但不得含辱骂或人身攻击。
5. 输出严格 JSON：{"free_text":"..."}

USER:
【真实感受】主导维度={{top_dim}}，最不匹配={{worst_dim}}，愿再见={{meet_again}}
【标记】ambivalent={{b1}} / emotional={{b2}} / terse={{b3}}
【对方画像关键词】{{partner_keywords}}
```

### 4.3 防"自证循环"（最容易踩的坑）

- Oracle 用**确定性函数 + 噪声**，不用与系统相同的 LLM；反馈文本生成用另一个模型
- `hidden_taste` 不得以任何形式进入问卷答案、persona 文本、日志、prompt（自动化泄漏扫描：禁止字段名单 + 每段注入文本正则检测）
- `taste_recovery` 的评判用**独立模型**，且每批次抽 5% 人工复核
- 不能让系统"学会 Oracle 的措辞"：反馈文本注入同义改写与噪声，评测看维度权重相关度而不是文本相似度

## 五、12 周期回放（完整生命周期，不是只跑匹配）

每个虚拟周期严格跑：

```
1. 偏好提交（截止/提醒/423）
2. 硬过滤（等时圈/拉黑/已配过/注销）
3. 五路召回 + RRF + 影子精确对照算 Recall@K
4. 粗排 → Top15 → Agent 分身模拟 → 裁判打分 → 记录 sim_report
5. 全池贪心配对（一人一位、饥饿优先、阈值）
6. 周三交付（mock sink，检查准时性与海报生成）
7. accept/refuse → 排期 → 签到 → 赴约（爽约按概率注入）
8. FeedbackOracle 生成反馈 → POST /api/feedback（走真实接口）
9. 画像重写（mp_persona 新版本）+ pair_memory + 裁判校准（≥30 条后）
10. EvalJob 计算本周期全部指标 → sim_cycle_metric
```

周期之间**状态连续**：画像版本累积、pair 记忆累积、饥饿队列累积、成本累积。这样才能验证"越匹配越准"，而不是每周重新洗牌。

## 六、评估指标（可计算、可验收）

| 指标 | 定义 | 目标 |
|---|---|---|
| `top1_hit@decile` | 被选中的 pair 的 `true_score` 落在该用户当周全部可行候选 top10% 的比例 | 周期 1 ≥35%，周期 12 ≥60% |
| `regret` | `(最优可行 true_score − 选中 true_score) / 最优` | 12 周期至少 8 个周期单调下降；末周期 ≤0.15 |
| `taste_recovery` | 独立评判模型把 `taste_text` 映射回 10 维打分，与 hidden_taste 求 Spearman ρ | ≥0.70（周期 12） |
| 口是心非组收敛 | 该组隐性维度（humor/expressiveness）在画像中的权重 > 显性维度（身高/学历） | ≥80% 用户在周期 8 前达成 |
| `pair_repeat_rate` | 重复推送同一对 / 拉黑后仍召回 | 0 |
| `stability` | 注入一次恶意差评后画像维度变化幅度 | ≤0.15，且下周期自动恢复 |
| `learning_slope` | regret 对周期号线性回归斜率 | <0 且显著 |
| 公平性 | 长尾 20% 用户曝光份额 / 人数占比 | ≥0.80 |
| 召回 | 见《召回策略规格》第七节 | 全部达标 |
| 工程 | 准时率、降级次数、成本 | 达标 |

**`taste_recovery` 是最硬的指标**：它直接回答"分身是不是真的越来越懂主人"，而不是靠赴约率这种受外部因素影响的间接指标。

## 八、验收与衔接

**阶段 B 出口**：第六节全部指标达标 + A 类 P0 用例 100% 通过 + A 类 P1 ≥95% + 召回专项闸门（见召回文档第七节）通过 + 成本与压测达标。未达标继续打磨，不进灰度。

**阶段 C（灰度）衔接**：
- 真实指标（接受率、赴约率、反馈提交率、"愿再见"率）与仿真预测对比，**偏差容忍带 ±20%**，超出即暂停灰度并回仿真复核 Oracle 假设
- 真实反馈**叠加**到画像，不覆盖合成期结论；合成回放继续每周并行跑，作为回归基线
- 灰度期间每周复盘一次 Go/No-Go 子表，任何 P0 事故立即回滚

## 九、常见陷阱（我提前兜住）

| 陷阱 | 后果 | 防线 |
|---|---|---|
| 隐藏真值泄漏进问卷/persona/日志 | 指标虚高，上线即崩 | 泄漏扫描 + 字段黑名单 + 代码评审 checklist |
| 合成用户太"干净" | 覆盖不到真实长尾 | 长尾配额 + 脏数据注入 + 口是心非组 |
| Oracle 与系统用同一模型 | 系统学到的是模型措辞 | Oracle 确定性函数 + 独立文本模型 + 独立评判模型 |
| 只看平均指标 | 最脆弱用户被牺牲 | 分桶报告（选择性桶、活跃度分层、口是心非组） |
| 周期之间状态重置 | 学不到"越学越准" | 回放状态持久化，断言周期号连续 |
| 仿真用简化代码 | 验证了个寂寞 | 生产代码 + DataSourceRouter，禁止仿真专用分支 |
| 只测匹配不测生命周期 | 签到/触达/注销出问题 | 12 周期跑完整 20 节点 + A 类用例 |

## 十、阶段 B 落地任务（可直接排期）

1. 建 `sim_*` 表 + Qdrant 独立 collection + DataSourceRouter / SimClock / mock sink
2. 合成用户生成器（3.4 prompt）+ 长尾配额 + 泄漏扫描
3. FeedbackOracle（3.3 函数 + 4.2 prompt）+ 噪声注入
4. SimDriver 12 周期回放 + EvalJob 指标实现
5. A01-A28 对抗用例自动化（每个都是可重跑的测试类）
6. 召回实验矩阵 E1-E14 + ANN 参数扫描（与召回文档并行）
7. 指标看板 + 影子对照日检 + 告警配置
8. Go/No-Go 评审材料（所有阈值实测值 + 实验记录 + 回滚预案）
