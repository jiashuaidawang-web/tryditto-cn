# V4-F03 标签政策

三个结果分开记，不合成一个“关系成功”位。

## Y1 双方回应

适用对象是已发布匹配。时间窗是该匹配自己的 `responseDeadline`。

| 状态 | 含义 | 能否作为 Y1 学习样本 |
| --- | --- | --- |
| `BOTH_ACCEPTED` | 双方都接受 | 能，正类 |
| `BOTH_DECLINED` | 双方都拒绝 | 能，负类 |
| `ONE_ACCEPTED` | 只有一方接受，另一方明确拒绝 | 能，单独一类，不算双方接受的负类 |
| `IMMATURE` | 截止前仍有 `UNKNOWN` | 不能标成失败 |
| `NO_RESPONSE` | 截止后仍无人查看 | 不能标成拒绝 |
| `EXPIRED` | 业务超时 | 保持超时 |
| `UNKNOWN` | 截止后仍有一方没有回应 | 不能标成拒绝或单方接受 |
| `WITHHELD` | 授权不是 `OPEN`，或来源已撤回 | 不进入未授权学习 |

`y1Binary()` 只包含双方接受和双方拒绝。

## Y2 见面

适用对象是这条匹配上的见面证据。时间窗是 `dateDeadline`。

`BOTH_ATTENDED` 和 `BOTH_ABSENT` 可以进入双方见面的二分类。一方到场、一方缺席各自保留。`CONTESTED` 保持争议，不裁决。窗口未到是 `IMMATURE`。没有见面环节是 `NOT_APPLICABLE`。

## Y3 继续交往

适用对象是见面之后的继续意愿。时间窗是 `followupDeadline`。

双方表达和双方拒绝可以进入二分类。只有一方表达保持为 `ONE_EXPRESSED`。窗口未到是 `IMMATURE`。

## 合成集上的分布

128 条里：双方接受 44，双方拒绝 24，单方接受 20，未成熟 8，无人响应 8，超时 8，授权关闭 8，截止后仍未知 8。见面双方确认 16，见面争议 8。双方继续 16。这些数字描述合成标签，不是真实用户比例。

## f03-labels-2

上面的表是冻结契约，由 `RelationshipLabels` 保留。`docs/v4/f03-observations.json` 和原来的校准表没有为了更好的指标改标签。

`ExplicitOutcome` 是新口径，版本 `f03-labels-2`。它不替换冻结标签。

Y1：

- 双方都明确接受：`BOTH_ACCEPTED`。
- 任一方明确拒绝，且观察条件成立：`NOT_MUTUAL`。这不是把未知或超时写成拒绝。
- 一方接受、另一方未知，截止后：`MISSING`。
- 任一方超时：`EXPIRED`。
- 截止前仍未知：`IMMATURE`。
- 截止后仍无人查看：`NO_RESPONSE`。
- 授权关闭或来源已撤回：`UNAUTHORIZED`。

Y2、Y3 同样把明确结果、单方结果、争议、未成熟和缺失分开。

同一 128 条上两种口径的样本量：

| 口径 | 数量 |
| --- | --- |
| 已发布 | 128 |
| 旧契约双方拒绝 `BOTH_DECLINED` | 24 |
| 新契约未达成双方接受 `NOT_MUTUAL` | 44 |
| 双方都给出明确接受或明确拒绝 | 96 |
| 任一方明确拒绝 | 44 |
| 超时 | 8 |
| 未成熟 | 8 |
| 无人响应 | 8 |
| 缺失 | 8 |
| 无授权 | 8 |

差出来的 20 条是旧口径里的单方接受。旧口径不把它们算进双方接受的负类。新口径把明确拒绝记成未达成双方接受，同时仍把未知、超时和未成熟留在各自的状态里。
