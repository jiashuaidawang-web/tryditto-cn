# V4-F03 评估设计

冻结数据集是 `f03-synthetic-1`，128 条独立观察，16 种情况各 8 条。开发集 96 条，保留集 32 条。划分键是用户编号和匹配周期，同一个人不跨两边。

16 种情况：

1. 双方接受。
2. 单方接受。
3. 双方拒绝。
4. 窗口未成熟。
5. 无人响应。
6. 匹配超时。
7. 见面结果有争议。
8. 一方撤回授权。
9. 画像版本钉在匹配当时，之后的版本不替换它。
10. 同一匹配有两条来源事件，仍是一条观察。
11. 同一用户出现在多个匹配周期里的多条开发集记录。
12. 六种策略各自有自己的已发布样本。
13. 高分双方拒绝。
14. 低分双方接受。
15. 分数和结果故意不一致。
16. 只有已发布样本，没有未发布配对的反事实结果。

标签按情况书写，不用待测分数生成。高分拒绝和低分接受都在集合里。

## 选择偏差

实验记录这些限制，计算时不把它们消掉：

- 只有已发布匹配才有反馈。
- 未推荐候选的真实意愿看不见。
- 愿意回馈的人不能代表全体用户。
- 见面反馈出现在接受之后。
- 继续交往反馈出现在见面记录之后。
- 窗口未到的样本是未成熟，不是失败。
- 同一个人多次出现，样本相关。
- 同一匹配的多条事件不是多条独立关系。
- 合成数据里为了检查标签而写下的结果，不是生产库里已有的字段。

开发集拟合，保留集评分。保留集标签不写进分箱比例、逻辑回归或保序阶梯。

指标和规则在 `StrategyEval`、`ScoreCalibration` 和 `StrategyComparison` 里。真实校准、真实策略提升和真实关系质量保持 `NOT_RUN` 或 `NOT_IDENTIFIED`。
