# V4-I01-FINAL 审计

本轮只收口产品集成的锁、环境和擦除声明。不实现影子匹配，不打开生产 V4。

## 锁顺序

相关事务现在都按同一层级获取锁：

1. 用户行锁，多人时按用户编号从小到大。
2. 反馈咨询锁，类 11，同一编号顺序。
3. 匹配咨询锁，类 12，只在工作点名一场匹配时获取。

注销在 `requestDelete` 里先锁用户行，再进入反馈擦除。学习确认和撤回先锁用户行，再取咨询锁，写入前再读账号、处理授权和代次。反馈追加和群体观察对双方使用同一顺序。提取任务的开始和完成也先锁用户行。

没有用加长锁等待掩盖死锁，也没有拿掉这些锁。PostgreSQL 并发测试覆盖注销对学习确认、反馈写入、群体观察、提取任务，双方同时注销，以及授权撤回对画像保存。测试有 20 秒上限。

## 环境

`LEGACY_ONLY` 仍是默认。`V4_INTEGRATION_TEST` 和 `V4_SHADOW_TEST` 必须同时具备隔离环境名、非生产 profile 和隔离库。`V4_SHADOW` 与 `V4_PILOT` 仍然不能启动。生产配置写死 `LEGACY_ONLY`，环境名是 `production`。

## 外部擦除

PostgreSQL 清理和外部任务分开。任务有编号，并绑定生命周期代次。没有执行器时状态是 `NOT_RUN`。失败原因不含长数字和密钥样式。调用方不能把任务标成 `DONE`。因此不能宣称账号的全部外部数据已经删除。Qdrant 执行器本轮 NOT_RUN，这是生产阻塞，不因此扩大到向量召回。

旧的待同步向量在用户不再是 `active` 时不会继续 upsert。注销后的提取完成写不回画像。

## 授权

匹配、画像处理和模型导出仍然分开。默认不授予反馈学习。影子测试模式也不授予。合成反馈上下文不是用户授权。真实反馈、个体学习和群体评估授权留到 I03。

## 浏览器

用户端 Playwright 覆盖隔离登录、真实入驻页面、提交问卷、完成后的隔离诊断、修改一项答案、未授权用户没有可用画像，以及注销后旧会话不能再读画像。画像处理授权没有产品界面，测试用只在隔离模式开放的 `/api/internal/profile-diagnostic`。它不接收调用方构造的画像。截图和日志由浏览器作业的 Artifact 保存。

## 还不能上线

真实用户影子运行、真实画像质量和真实关系质量都还没有做。生产启用 NO-GO。最终匹配算法质量 NO-GO。
