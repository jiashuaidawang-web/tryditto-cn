# V4-M04 优化目标

默认目标是 G2，版本 `global-objective-g2-1`。G3 和 G4 只作对照。

契合度 `fitCenti` 是 1–10000 的整数。优化权重是求解器看到的另一个整数。关系写在 `OptimizationWeight.RELATION`。

## 优先级

| 目标 | 求解器 | 优先级 |
| --- | --- | --- |
| G0 | 贪心 | 按边权从高到低取，不回头 |
| G1 | Blossom | 最大总契合度 |
| G2 | Blossom | 先最大合法配对数，再最大总契合度 |
| G3 | Blossom，先删边 | 先留下契合度、方向分和覆盖率都过冻结门槛的边，再执行 G2 |
| G4 | Blossom | 先最大配对数；人数相同时，契合度与最多 400 的合成公平加成分一起比较 |

G3 的门槛在运行前冻结：契合度至少 80，方向分至少 80，双向覆盖率至少 0.80。公平加成分是每侧合成未匹配周数乘 100，每侧最多 4 周，一条边最多 400。它不降低安全门槛，也不把未匹配写成用户标签。

## 编码

G2 和 G3 的每条边是 `cardinalityBase + fitCenti`。`cardinalityBase = 最大配对数 * 10000 + 1`。少一对时，即便每条边都是满分，总权重仍然小于多一对且每条边只有 1 分的匹配。这个差在 10,000 人的上限上由测试锁住，并且总权重小于 `2^52`。

G4 不能沿用这个 base。公平加成分加在满分之上。若 base 只比满分多 1，几十条边的加成分之和会盖过“多配一对”。修正后的 `g4Base = (最大配对数 - 1) * 10400 + 1`，每条边再加 `fitCenti + fairness`。10,000 人的测试同时检查：多一对的最小权重大于少一对的最大权重，总权重仍小于 `2^52`。人数相同的时候，400 的加成分仍然可以胜过 3 分的契合度差。这是公平实验要观察的质量移动，不是安全豁免。

G3 不是把质量门槛编进权重。低于门槛的边先离开求解池。现有最大权匹配因此可以正确表达 G3。它不能表达“尽量多配，但用连续惩罚代替硬门槛”。本轮没有做这种连续惩罚。

## 小图对照

穷举最优和求解器的边集合一致。

| 图 | 对照 | 结果 |
| --- | --- | --- |
| 局部最优 | G0 取 1–2 与 3–4，契合度 110 | G1 取 1–3 与 2–4，契合度 180 |
| 人数 | G1 只留 100 分的一对 | G2 留两对 40 分，总契合度 80 |
| 质量 | G2 会留下 70 分边 | G3 只留 90 分边，另外两人是 `OPTIMIZATION_NOT_SELECTED` |
| 公平 | G1 留 100 分 | G4 留 97 分加上 4 周合成历史的那条边，权重 10101 |
| 三角形、奇数点、空图 | 与穷举一致 | 允许一人不匹配，空图配对数是 0 |

G3 的未匹配原因没有单独的“低于质量层”代码。被门槛删掉的边仍在诊断求解图里，所以原因落在 `OPTIMIZATION_NOT_SELECTED`。报告读这个原因时要同时看该边是否低于 80。

## 17 人 cohort 上各目标

开发和保留的合格边契合度都是 100。G0、G1、G2、G3 的配对集合相同：5 对，总契合度 50000，安全违规 0。G4 的配对数和总契合度也相同，红组内部的搭档变了，因为 `base+3` 的 400 加成分只改变并列边的选择。这套 cohort 不能用来区分 G0 和 G1 的质量。那个差别只在上面的小图里出现。

G2 的优化权重是 450005。G4 的优化权重是 414405。这两个数不能互相比较大小，因为 base 的定义不同。比较目标时看配对数和 `fitCenti`。
