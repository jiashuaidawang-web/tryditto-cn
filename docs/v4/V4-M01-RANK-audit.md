# V4-M01-RANK 召回与评分审计

审计对象是已经冻结的 M01 召回和 M02 双向评分。本轮没有改 `V4RecallEngine` 的权重、`RrfFusion` 的 userId 次序、`CompatibilityDecision` 或生产 `WeekRunner`、`Scorer`、`MatchingSolver`、Blossom、S01。

历史数字保持原样，只作诊断：

- M01 挑战保留集 Recall@20 仍是 7/45，和随机合法池相同。
- 8 条强满足分离实验仍是 Top-20 为 0/8、Top-50 为 4/8、完整合法池为 8/8。

这两份结果已经看过，不作为本轮泛化证明。

## 召回 Map 丢掉了什么

`RecallSubject` 给路线使用的只有三块：`selfEnums`、`preferenceEnums`、`hobbies`。`CompatibilitySubject` 上的完整自身特征和完整偏好不进入这三块。

`RecallProfileContract.admit` 在进入 Map 之前还会丢掉空白、未知、未注册、非普通枚举、不公开、无界和互相矛盾的声明。爱好还要求官方评分所接受的证据支持。被丢掉的项不会留在路线里。

本轮夹具把这个损失写成可见的事实。开发集寻求者的完整画像是 `slow/quiet/low/early`，偏好也是这四项，爱好是 `reading`。召回 Map 只保留 `self.pace=slow`、`partner.pace=slow` 和 `reading`。沟通、社交主动性和日程没有路线可读的副本。

40 名干扰候选的完整画像是 `fast/frequent/high/late`。他们的召回 Map 被故意写成和寻求者一样。路线因此看不见冲突。4 名隐藏强匹配的完整画像和寻求者一致，召回 Map 是空的，爱好写成 `gym`。

## 为什么相似干扰候选占住前排

R1 到 R5 的原始分只要大于 0 才进入该路。同分时较小 `userId` 先得到名次。RRF 使用名次，不使用原始分：

`score = Σ weight / (60 + rank)`

权重仍是 R1 1.0、R2 0.8、R3 1.0、R4 1.0、R5 0.7、R6 0.3。本轮实验没有启用 R6。

干扰候选、可见强匹配和单向候选共用同一份召回 Map，所以每一路的原始分相同。较小 id 拿走较好的名次，RRF 分变成严格递减，最终不再出现同分。开发集融合后的相邻同分是 0/44。`RrfFusion` 末尾的 userId 次序没有再改动任何人。偏差发生在名次分配，不发生在最后一次并列比较。

开发集有 40 名干扰候选。路线预算 50 还能看见 4 名可见强匹配，他们的融合名次是 42 到 45。最终保留 20 人时，这 20 人都是较小 id 的干扰候选。保留集有 50 名干扰候选。路线预算 50 时，3 名可见强匹配进不了该路，融合 Recall@50 是 0/6。

## 为什么 4 个强匹配的召回 Map 为空

这 4 个人不是没有画像。完整自身和完整偏好都是理想值。召回 Map 被建成空表，爱好是 `gym`，和寻求者的 `reading` 不相交。每一路原始分都是 0，0 不进入名单，融合里没有他们。

这不是粗排把他们删掉。他们没有到达粗排。开发集窄召回把这 4 人记为 `NO_ROUTE_SIGNAL`，另外 4 名可见强匹配记为 `COARSE_INPUT_CUT`。

## 低 userId 为什么长期占优

原基线没有改。相同路线分永远先排较小 `userId`，名次一旦写入，RRF 分就不再并列。四个周期都保留前 20 时，userId 策略暴露 20 人，每人出现 4/4 次，其中 20 人全是特征相同的干扰候选。8 名手写强匹配在 4 个周期里缺席 32/32 次。

实验性并列策略只作用在路线分相等的位置，不改 `RrfFusion`。固定种子每个周期都是同一组 20 人，但和 userId 组不同。按周期变化的散列在 4 个周期里暴露 45 人，同一人最多出现 3 次，40 名同特征干扰候选都出现过。双向覆盖优先把完整画像命中数更高的人排在相等路线分之前，强匹配缺席降到 16/32；这 16 次正好是 4 名空 Map 强匹配乘 4 个周期，可见强匹配不再被截断。受控探索在 4 个周期里暴露 29 人，强匹配缺席仍是 31/32。探索名额大多仍落在干扰候选上。五种策略重复运行结果一致。

## 哪些路线带来低价值候选

在这份夹具上，R1、R2、R3、R4 对同一份残缺 Map 给出同一批人。可见强匹配的路线记录是 `R1+R2+R3+R4`，没有 R5。把每路预算从 20 加到 200，只是让更多相同 Map 的干扰候选留下。空 Map 的人仍然没有任何一路。低价值候选不是单独一路的权重问题，而是四路都在读同一份被截短的 Map。

## M02 能否做合法候选粗排

可以，而且必须调用现有的 `BidirectionalCompatibilityEngine.v1().decide`。推荐资格仍只由 `CompatibilityPolicies` 的冻结 B5 门决定。粗排可以改变谁先被送到这个门，不能另写一套双向分，也不能用信息少来判某人非法。

只在 RRF 名单上做 M02，只能找回已经进入融合的人。开发集宽召回下，正向分、双向最低分和覆盖率调和平均都是最终覆盖 4/8，丢失的 4/8 全部是 `NO_ROUTE_SIGNAL`。保留集同样是 3/6，丢失的 3/6 也是空 Map。

完整合法池和全画像预筛选把空 Map 的人送进同一个 M02 门。两套集合上的手写强匹配都被覆盖，干扰候选被评分且没有获得推荐资格。

100 人的单边时间包含启动，不能拿它乘到 10,000 人。1,000 人之后单边大约 1.4 µs，10,000 人的全图时间和边数同阶。堆样本包含每一边的耗时记录，不是评分本身的常驻内存。引擎召回是一个寻求者、路线上限 50、融合预算 50，不是宽召回预算 200。向量检索没有执行。

事先冻结的墙钟是 90 秒。五个规模都在本机测完，没有用线性外推代替未测规模。

## 预算和覆盖的关系

最终保留预算固定为 20。加宽 RRF 不能把强匹配送进这 20 人。开发集路线预算至少 50 时，4 名可见强匹配进入融合前 50，再被最终 20 截掉。保留集要到路线预算超过 50 名干扰候选，可见强匹配才进入融合，然后仍被 RRF 排在最终 20 之外。空 Map 的人在 20、50、100、200 四个预算下都不进入 RRF。

全画像预筛选在粗排预算 20 时已经覆盖两套集合的全部手写强匹配。原因是这份夹具里干扰候选的完整画像每一项都相反，命中数和强匹配完全分开。这是夹具的构造，不是把粗排预算定成 20 的理由。
