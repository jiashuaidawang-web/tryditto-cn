# V4-F01 指标

`FeedbackMetrics` 只数已经成熟的已发布配对。未成熟的配对增加 `immature`，不进入分母，也不算失败。`UNKNOWN` 和 `EXPIRED` 都不算拒绝。

观察窗口由调用方标成成熟或未成熟。去重口径是一次配对，不是一条事件。下面的分母都是这个窗口里的成熟已发布配对数，另有一行单独使用「双方至少有一侧已经接受或拒绝」的配对数。

| 指标 | 分子 | 缺失时 |
| --- | --- | --- |
| `view_rate` | 至少一侧有查看事件 | 没查看的不计入分子 |
| `one_accept_rate` | 至少一侧响应是 `ACCEPTED` | 未知和超时不算接受 |
| `mutual_accept_rate` | 投影 `mutualAcceptance` | 单方接受不算 |
| `decline_rate` | 至少一侧响应是 `DECLINED` | 超时、未知、撤回都不算 |
| `expiry_rate` | 至少一侧是 `EXPIRED`，且没有拒绝 | 已经接受的那一侧仍算接受，超时的那一侧算超时 |
| `schedule_rate` | 安排过，含后来取消 | 窗口结束仍没有安排是 `NOT_OCCURRED`，不算安排 |
| `reported_attendance_rate` | 单方或双方报告见到了 | 争议报告不计入 |
| `mutual_attendance_rate` | 双方都报告见到了 | 单方报告不算双方确认 |
| `one_continue_rate` | 至少一侧表达继续 | 未知不算不愿 |
| `mutual_continue_rate` | 两侧都表达继续 | 一侧愿意不算双方愿意 |
| `coverage_rate` | 至少一侧已经接受或拒绝 | 只有未知或只有超时不算覆盖 |
| `contest_rate` | 见面报告是争议 | 还没报告不算争议 |
| `retract_rate` | 反馈被撤回 | 处理授权撤回另计 |
| `processing_revoked_rate` | 处理授权被撤回 | 不并进撤回率 |
| `learning_eligible_rate` | 事实资格为真 | 资格为否的留在分母里 |

另外两个比例的分母是已经有人响应的成熟配对，不是全部已发布配对：

- `one_accept_rate_among_responded`
- `mutual_accept_rate_among_responded`

十个虚构案例里这两个分母碰巧也是 10，因为每个案例都有响应。定义仍然分开，不能把「已发布」和「已响应」混成一个名字。

这十个案例的已发布口径是：查看 1/10，单方接受 10/10，双方接受 7/10，明确拒绝 2/10，超时 1/10，安排见面 3/10，单方或双方报告见面 1/10，双方确认见面 1/10，单方继续 2/10，双方继续 1/10，覆盖 10/10，争议 1/10，反馈撤回 0/10，处理授权撤回 1/10，学习资格 7/10。双方接受在已响应口径下也是 7/10。撤回率是 0，因为撤回出现在并发测试里，不在这十个案例里。

F01-FINAL 在同一分母上增加：

| 指标 | 分子 | 分母 |
| --- | --- | --- |
| `either_response_rate` | 至少一侧已经接受或拒绝 | 成熟已发布配对 |
| `both_response_rate` | 两侧都已经接受或拒绝 | 成熟已发布配对 |
| `user_accept_rate` | 接受的参与者侧次数 | 成熟已发布配对 × 2 |
| `date_report_coverage` | 见面状态不是未知、保留或不适用 | 成熟已发布配对 |
| `continue_coverage` | 至少一侧表达了继续或不再继续 | 成熟已发布配对 |

`mutual_attendance_rate` 就是双方确认见面率。`mutual_continue_rate` 就是双方继续意愿率。十个案例上新指标是：至少一方响应 10/10，双方均响应 9/10，用户级接受 17/20，约会报告覆盖 2/10，后续意愿覆盖 2/10。

`summarize` 仍允许调用方把同一个 `matchId` 传两次，用来保留原来的未成熟重复实验。`summarizeDistinct` 遇到重复 `matchId` 抛出 `DUPLICATE_MATCH`。

`UNKNOWN`、`EXPIRED`、`WITHHELD` 不进入拒绝分子，也不进入约会报告覆盖分子。没到达观察窗口的配对记在 `immature`，不记成失败事件。

各事件自己的成熟窗口由调用方在 `mature` 里给出，本轮不把窗口长度写成已验证参数：

- 响应：发布后到该配对周期的响应截止。
- 见面安排：双方接受之后到安排截止。
- 见面报告：安排时间之后到报告截止。
- 继续意愿：见面报告之后到继续意愿截止。

窗口未到时该配对保持未成熟。迟到的查看可以记下来，但不能把已经生效的接受或超时改掉。
