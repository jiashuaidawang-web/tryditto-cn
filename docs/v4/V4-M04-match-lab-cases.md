# V4-M04 Match Lab 案例

结构化记录在 `docs/v4/m04-match-lab-cases.json`。十个案例都包含用户、求解边、被拒绝边、G0 到 G4 的配对、未匹配原因和安全计数。本轮没有前端。

读一条配对时，先看求解边里的双向分和资格，再看其他目标是否选了另一条边。用户与 B 匹配而不是与局部分数更高的 C 匹配，对应案例是局部最优：C 是 100 分的 1–2，B 是两条 90 分边。贪心留下 C。Blossom 留下两条 90 分，总契合度 180。

## 案例

1. `local-optimum`。四个人，边是 100、90、90、10。G0 取 100 加 10。G1 到 G4 取两条 90。安全 0。
2. `cardinality`。G0 和 G1 只留 100 分。G2 和 G4 留两对 40 分。G3 的 80 分门槛删掉 40 分边，回到单独的 100 分。被删掉的两人原因是 `OPTIMIZATION_NOT_SELECTED`。
3. `triangle`。三条边都连在三个人之间，不是男女二部图。G1 只留 50 分的一对，第三人是全局竞争。
4. `odd-node`。三个人只有一条 80 分边。第三人是 `NO_LEGAL_CANDIDATE`。
5. `empty`。三个人，没有边。三人都是 `NO_LEGAL_CANDIDATE`。配对数 0。
6. `topk-full`。全图 G2 取 1–2 与 3–4，总契合度 130。1–3 的 100 分没有被选，因为它会拆开两对。
7. `topk-1`。1–2 被局部第一名挤出图。G2 只剩 1–3。`fullPopulation` 为 false。这是截断图的最优，不是全图最优。
8. `quality-tier`。90 分边留下，70 分边不进入 G3。安全 0。
9. `fairness`。用户 3 有 4 周合成未匹配历史。G0 到 G3 留 100 分的 1–2。G4 留 97 分的 1–3。契合度下降 3 分。没有降低安全门槛。
10. `dev-cohort`。17 个合成画像。求解边 16 条，拒绝边 120 条。G2 发出 5 对：`40001-40002`、`40003-40051`、`40011-40012`、`40021-40022`、`40052-40081`。手写标签是后两对蓝组和绿组。红组三人只能有一对，第三人与其他红画像配对。撤回、过期、同意撤回、空画像、部分重叠、单向和年龄硬约束留在未匹配里。G4 把红组搭档换成 `40002-40003` 与 `40001-40052`，总契合度仍是 50000。

保留集使用另一套取值和 50000 起的编号，不在这个 JSON 里重复展开。它的 G2 同样是 5 对、标签 2/2、安全 0。

拒绝边的 `exclusion` 是追踪原因的入口。未匹配的最终原因是一个人一个代码，诊断列表可以有多项。这些代码不是性格描述，也不能当作负反馈。
