# V4-M04 性能报告

机器是本轮开发机。时间是单次运行，不是多次中位数。堆数字是求解返回时 `totalMemory - freeMemory` 的一次采样，不是分析器里的峰值。1,000 人的采样是 0，因为求解没有开始。

E 的预检写在评分循环里，`filterMs` 为 0 表示没有单独计时。F 的 `filterMs` 才是结构短名单的时间。画像准备在这些规模上不到 1 ms。

## F 和 Top-K

F 只对短名单并集调用 M02。

| 用户 | F 求解边 | F 的 M02 | F 配对数 | F 总契合度 | F 安全 |
| ---: | ---: | ---: | ---: | ---: | ---: |
| 100 | 1,370 | 28 ms | 50 | 500000 | 0 |
| 500 | 9,370 | 92 ms | 60 | 600000 | 0 |

F 在 500 人上更快，也少了 190 对。速度不能单独作为选择理由。

Top-K 不再评分，只从已经建好的合格图里取边。500 人的完整求解是 215 ms。同一轮里 Top-10、Top-20、Top-50 的求解都返回了，边数更少，时间包含在这次规模测试的 3.6 秒墙钟里。它们的最优只对截断图成立。

## 预算

50,000 条求解边和 90 秒墙钟在运行前冻结。500 人的 41,422 条边、215 ms 求解和约 97 MB 的堆采样还在预算内。1,000 人的合格边超过 50,000，求解器没有构造那张 Java 图。5,000 与 10,000 未启动。

本轮不解决任意规模的分布式图优化。完整合格图在这个重复调色板上的可运行上限是 500 人。
