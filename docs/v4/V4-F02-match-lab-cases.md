# V4-F02 匹配回放

十个虚构案例在 `docs/v4/f02-match-lab-cases.json`。每个人都是合成夹具。评分使用现有的 `BidirectionalCompatibilityEngine` 和 `V4GlobalMatchingEngine`，没有改 M02 或 M04 的参数。

分数是系统行为。它不证明真实关系变好了。

初始池里，91001 的沟通是高频，并希望对方也是高频。91002 是安静。91003 是直接。91004 自述直接、希望对方高频。确认之前，全局配对是 91001-91004 和 91002-91003。

| 案例 | 发生了什么 | 双向分 | 全局配对 |
| --- | --- | --- | --- |
| L01 | 自述沟通改成安静 | 对 91002 从 75/75 变成 75/100 | 改成 91001-91002 与 91003-91004 |
| L02 | 希望的对方沟通改成安静 | 对 91002 从 75/75 变成 100/75 | 同样改成 91001-91002 与 91003-91004 |
| L03–L07、L09 | 拒绝、超时、未见面、对方评价、一次不满、拒绝提案 | 分数不变 | 配对不变 |
| L08 | 三次同方向自述后，用户确认自己和偏好都改成安静 | 对 91002 变成 100/100 | 91001-91002 的 fitCenti 变成 10000 |
| L10 | 撤回刚才确认的自述 | 分数回到确认前 | 配对回到确认前 |

安全违规在十个案例里都是 0。
