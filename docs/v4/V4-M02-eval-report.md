方向没有对调的单向关系是 8/8。同一次本地运行里，双向引擎 P50 是 107885 ns，P95 是 280579 ns。V3 `Scorer` 的 P50 是 28039 ns，P95 是 68572 ns。换一次运行这些纳秒会变，不作为选择门槛。

选中方法是 B5。B3 和 B4 的成对正确数相同，都低于 B5。B3 会把覆盖率 0.25 的 100 分排到有证据的 75 分前面，并把它推荐出去。B2 还会把 100/25 的算术平均 62.5 排到双向 50 分前面。B6 把强偏好满足率 0.50 的双向 50 分也变成未定义，成对正确数下降。调和平均本身不是这套对照里的最佳实验候选。

## 保留集

30 条，99 组成对。不参与选择。B5 是 99/99，单向误推荐 0/3，证据不足误推荐 0/9，硬约束违规 0。其余方法的相对顺序和开发集相同。

保留集更换了中等分、单向和部分满足落在哪一个维度上，关系形状仍是同一组对照。NDCG 为 1 只说明 B5 在这些事先构造的对照上排对了，不是开放世界证明。

## 召回损失和评分损失

M01 挑战保留集 Recall@20 仍是 7/45，权重没有重调。

另有一个 8 条偏好强满足的合成池。45 名召回特征相同的人因为较小 `userId` 占住前列。4 条强满足能被 R1–R5 看见，另外 4 条的召回 Map 是空的，完整画像却是匹配的。

| 池 | 被召回的强满足 | 评分阶段能看到的强满足 |
| --- | ---: | ---: |
| Top-10 | 0/8 | 0/8 |
| Top-20 | 0/8 | 0/8 |
| Top-50 | 4/8 | 4/8 |
| 完整合法池 | 8/8 | 8/8 |

Top-20 上的评分质量没有材料，因为正确的人没有进列表。完整池上这 8 条都能评出不低于 60 的最低方向分。评分没有补上召回漏掉的人。

## 结论

离线双向评分按冻结规则是 GO。这个 GO 只覆盖上述合成对照。召回端到端仍是 NO-GO。真实模型推理 NOT_RUN。生产启用 NO-GO。最终匹配算法质量 NO-GO。
