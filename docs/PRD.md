## 1. 定位、演示目标与范围

### 1.1 一句话定位

「见一面」（暂定名）面向中国在校大学生，每周三晚上给你配一个人，并安排好时间和地点，让两个人线下见一面。它没有滑卡，也没有聊天框。产品形态 1:1 复刻美国的 Ditto（01 §1、§2），内容按中国大学生的习惯本地化。

### 1.2 演示目标

这次交付的是一个**细节完整、可以在服务器上演示**的 DEMO，用来给合作方、投资人或学校看「这个东西长什么样、怎么用」。

- **访问地址**：现在用 http://124.223.220.245；ICP 备案下来以后切换到 aiditto.cn。
- **验收方式**：看界面、交互和动效是不是和 Ditto 一模一样；中文内容是不是像中国产品；匹配闭环能不能在 5 分钟内完整走一遍（第 9 节）。
- **合规定位**：DEMO 不对公众开放，第 8 节列的所有合规事项仍然是**上线前关卡**。演示期只要求做到「不收集真实个人信息、不冒充已上线产品」。

### 1.3 范围

**范围内：**

- 营销首页 `/`，包括开场动画；登录页 `/login`。
- 完整入驻问卷：学生和非学生两条路径，8 个兴趣分支全部可达，附加页面也都在。
- 登录后的全部页面：首页、约会范围、个人资料、编辑、深度信息、屏蔽名单、账户、菜单、邀请。
- 匹配闭环（【推断设计】）：匹配海报 → 接受或拒绝 → 选时段并确认 → 约会当天签到 → 反馈 → 双方都想再见时交换微信。
- 演示控制面板（`?demo=1` 与 `/demo`）、运营后台（立即触发本周匹配、约 200 个合成用户、演示账号、重置演示账号）。
- AI 红娘：调用 LongCat-2.5 生成匹配理由、约会方案和可选的画像摘要，Qwen 作为备用。

**范围外（演示期不做）：**

- 真实短信和邮件发送（登录固定码 888888；学校邮箱验证码随便填 6 位数字都能过）。
- 支付、站内聊天、App 和小程序、学信网核验、人脸核验、AI 生成照片。
- Ditto 的 Sidequests、Doubles，以及邀请返现（07 §2 能看到这些路由，但 v1 §3.3 已经决定不做）。

### 1.4 与 v1 的关系

v1 是「先在 1～2 所学校跑通」的最小版本，很多地方故意比 Ditto 简单。v2 改成「先 1:1 复刻，再本地化」。主要变化如下：

| 项目 | v1 | v2 |
|---|---|---|
| 问卷 | 自行设计的 10 页左右 | 1:1 复刻 Ditto 两条路径约 30 页，中文隐藏敏感题（第 4 节） |
| 身高 | 默认不收集（v1 §10 第 6 项） | 收集（1:1），单位默认 cm |
| 性别选项 | 男 / 女 | 男 / 女 / 非二元 / 其他（1:1）；「想认识的性别」仍然按敏感信息处理 |
| 非学生路径 | 不服务 | 演示保留以对照 Ditto；上线是否保留，见决策项 |
| 联系方式 | 见面后双方都选「想」才交换 | 不变；Ditto 是确认时间后交换手机号（01 §4.3），我们不跟 |
| 大模型 | DeepSeek / Qwen（技术方案） | LongCat-2.5 为主，Qwen 备用（第 5 节）；`docs/技术方案.md` 需要同步修改 |
| 运营后台 | 内部人工台 | 演示用后台：一键触发匹配、合成用户、重置账号（第 7 节） |

## 2. 复刻原则

总原则：**看得见的形式 1:1，承载的内容本地化，有法律或安全风险的直接删除。** 遇到冲突时，删除优先于本地化，本地化优先于 1:1。

### 2.1 1:1 照搬

| 项 | 依据 |
|---|---|
| 视觉 token：选项胶囊 `#E40089`、深色背景 `#233039`、气泡圆角 28px、字体层级、间距 | 05 §1、§6；09 §7 |
| 页面结构：顶栏（锁形隐私按钮）、三段进度条、对话气泡式提问、底部 Next/Send 按钮 | 09 §7；10 §7；12 §4.4 |

## 4. 入驻问卷

题目全文、选项、中文文案都在 `web/src/onboarding/questions.ts`，页序和分支逻辑在 `web/src/onboarding/flow.ts`，本节只写规则，不重复题目原文。

### 4.1 进度条与页面模型

问卷分 3 段，进度条也是 3 段，每段的填充比例等于「本段第几格 / 本段格数」（12 §4.4）。每一页记为 `{段, 格, 本段格数, 是否跳过, 是否隐形}`。被跳过或隐形的页面仍然占格，所以进度条的跳动和 Ditto 一致（12 §2.6）。中文版隐藏的 8 题**不占格**，各段的分母会重新计算。

### 4.2 页序

**第 1 段（两条路径相同）**：是否学生 → 名字 → 性别 → 想认识谁 → 生日。

**学生路径（`isStudent = 是`）：**

- 第 2 段：兴趣 → 分支追问 → [民族 → 期望民族] → 期望年龄 → [体位两页] → 身高 → 身高范围 → 学校邮箱 → 验证码 → 照片 → 位置。
- 第 3 段：偏好过场页（隐形）→ 关系期待 → 匹配节奏 → 年级 → 来源 → 雷区 → [政治 → 政治重要度 → 宗教 → 宗教重要度] → 开场白 → datingHelp（最后一页）。

**非学生路径（`isStudent = 否`）：**

- 第 2 段：期望年龄 → [民族 → 期望民族] → [体位两页] → 身高 → 身高范围 → 兴趣 → 分支追问 → 照片 → 位置。
- 第 3 段：偏好过场页 → 关系期待 → 匹配节奏 → 职业 → 首次约会预算 → 雷区 → 学历 → 学历重要度 → [政治 … 宗教重要度] → 开场白 → datingHelp → 个人邮箱 → 验证码（最后一页）。

方括号内的页面在中文版不出现。Ditto 的尾段有长短两种（12 §1）。`FlowFlags.tail` 默认取 `long`，也就是所有页都出现；`?tail=auto|short` 用来回放调研录屏里的短尾段。

### 4.3 分支规则

1. **兴趣分支**：每个选中的兴趣对应 2 题追问，最多展开 **3 个**兴趣（`BRANCH_LIMIT`）。展开顺序按**题库顺序**：做饭、音乐、旅行、阅读、健身、游戏、影视、艺术，**与点选顺序无关**。这一点【已证实】，12 §2.3 推翻了早先「按点选顺序」的说法。
2. **取消兴趣**：回去取消某个兴趣时，清空它的分支答案（12 §2.4，`staleBranchKeys`）。
3. **体位两页**：只有「男 → 只想认识女」和「女 → 只想认识男」不出现，其余组合（包括非二元、「都可以」）都出现（12 §2.2；07 §4 的触发条件）。中文版一律隐藏。
4. **偏好过场页**：非学生路径显示；学生路径隐形但占格（12 §2.5、09 §20）。
5. **学校邮箱出口**：学生可以点「不是学生？不用学校邮箱继续」，此后按非学生尾段走，并改为在结尾验证个人邮箱（10 §7、`emailToVerify`）。走出口的人在上线版不进入学生池（v1 §4.2）。
6. **「欢迎回来」与跳题**：带草稿重新进入时显示「欢迎回来」提示（12 §0.1）；已答过的页面在 `skipAnswered` 开启时显示 0.9 秒转圈后跳过。
7. **最后一页**：学生路径的 datingHelp 是最后一页，撒花，点第一个选项就提交，随后播放心形点动画，1.9 秒后进入 `/home`（09 §6）。非学生路径的最后一页是邮箱验证码，datingHelp 不撒花（12 §5）。
8. **未满 18 岁**：生日换算不满 18 岁时弹出年龄确认层（09 §5）。中文版确认后**不能继续**，显示「见一面仅面向 18 岁以上的在校大学生」。

### 4.4 中文版校验与默认值

| 字段 | 规则 |
|---|---|
| 学校邮箱 | 演示期接受 `.edu.cn` 或 `.edu` 结尾（`validate.ts`）；上线改为试点学校学生邮箱后缀白名单（v1 §4.2） |
| 验证码 | 任意 6 位数字（演示） |
| 期望年龄 | 默认 18–24；滑块下限 18；学生上限 35，非学生上限 50（13 §4 第 15 项） |
| 身高 | 默认 170cm |
| 兴趣 | 1–5 个（09 §10.2）；本地兴趣是否增加见决策项。如果增加，只作为普通胶囊，不新增分支 |
| 照片 | 至少 2 张（`photos` 校验） |
| 位置 | 必须选中一个地点 |
| 隐私说明 | 敏感题下方写「仅用于匹配，不会公开」（`PRIVATE_NOTE`） |

### 4.5 完成之后

## 5. 匹配与 AI 红娘

### 5.1 原则

匹配由**程序**决定，大模型只负责「写」，不负责「选」。这与 04 §3.3 和 v1 §5 一致，原因有两个：第一，算法备案要求能解释配对逻辑（03 §3）；第二，大模型会编造地点和理由（01 §9.1 里有用户抱怨 Ditto 的理由太空泛）。

### 5.2 配对算法

1. **硬过滤**：以下任意一条不满足，这一对就不能配。
   - 双方的性别都在对方「想认识」的范围内。
   - 双方年龄都在对方的期望范围内；身高同理，选了「不在意」的跳过。
   - 双方的约会范围（等时圈）有交集；演示期用直线距离近似。
   - 不在任何一方的屏蔽名单里（按手机号或邮箱比对）；没有互相举报过；过去没有配过对；一方拒绝时勾选过「不再匹配」的也排除。
   - 学生之间的年级差在当前年级窗口内（04 §3.3）。
   - 双方都已完成入驻，至少有 2 张照片，本周没有暂停，也不在处罚期。
2. **打分**：兴趣重合（分支答案重合加分更多）、关系期待相近、年级接近、同校加分、距离越近越高，再减去拒绝项。按 04 §3.3，权重写在配置里，并用单元测试锁定；具体数值由我们定，后台可以调整。
3. **节奏门槛**：「匹配节奏」越挑剔，门槛越高（01 §3.1）。一对人的门槛取双方中较高的那个，分数不到门槛就不配，宁可空周。
4. **求解**：在所有通过的边上做最大权匹配，每人每周最多配一个（04 §3.3 推荐 CP-SAT；演示规模约 200 人，用同一套实现）。
5. **雷区复核**【推断设计】：对配上的每一对，把双方的「雷区」文字交给大模型做冲突自检。模型**只能否决、不能挑人**。被否决的这对作废，这两个人回到池子里再解一轮。否决原因记日志，后台可以看到。

### 5.3 模型与降级

- **主模型**：LongCat-2.5，走 OpenAI 兼容接口。**备用**：Qwen。
- **超时**：建议单次调用 15 秒超时，失败重试 1 次后切换到备用模型。备用模型也失败时，改用模板理由，逻辑与 `mock.ts` 的 `reasonsFor` 相同：从共同兴趣和本人的分支回答拼出。模板理由标「系统生成」，不标「AI 生成」。
- **密钥**：只放在后端，前端不直接调模型。
- **提示词输入**：只放问卷里的文字回答。「想认识的性别」、照片、手机号、邮箱、身高都不进提示词（v1 §6.1）。
- **已知缺口**：04 §2.1 的价格和备案表里没有 LongCat，备案状态和价格都**没有调研**。`docs/技术方案.md` 仍然写的是 DeepSeek 和 Qwen，需要同步修改。

### 5.4 AI 产出

| 产出 | 内容 | 约束 |
|---|---|---|
| 匹配理由 | 3 条，每条带 `basis`，说明依据是哪些字段 | 只能引用双方填过的内容，不得推测性取向、家庭、收入；不提身高和照片；每条不超过 40 字；用户可点「这条不对」，计入反馈 |
| 约会方案 | 地点、活动、两条开场提示（v1 §4.4） | 程序先按营业时段、双方约会范围交集、公共场所规则，从地点库挑 2–3 个候选；模型只能在候选里选一个，并写活动描述。程序校验地点 ID 必须在候选内，否则用第一个候选。不得建议饮酒、夜间户外或私人场所（v1 §5） |
| 画像摘要（可选） | `/you` 顶部「见一面眼中的你」，2–3 句 | 用户可以关闭；只用于展示，不参与配对 |

所有 AI 文字都带「AI 生成」标签（03 §2.4）。上线前须完成算法备案，以及生成式 AI 的使用登记（03 §2–§3）。

### 5.5 调用时机

后台触发匹配时，先给涉及演示账号的配对实时生成理由和方案，保证演示时马上能看到；合成用户之间的配对放到后台异步生成，没生成完的先显示模板理由。

## 6. 约会闭环

### 6.1 每周节奏（Asia/Shanghai，沿用 v1 §4.1）

| 时间 | 事件 |
|---|---|
| 周二 23:59 | 本周报名截止，锁定名单 |
| 周三 19:00 | 发布匹配（Ditto 同为周三晚上，01 §4.2；但它的时区没有确认，01 §12） |
| 周四 22:00 | 接受 / 拒绝截止 |
| 双方都选「去」的当下 | 系统求时段交集，发出时间方案 |
| 方案发出后 12 小时内，且不晚于见面前 12 小时 | 双方确认截止 |
| 周五至下周二，每天 12:00 / 15:30 / 18:30 | 可约会时段，每档 1 小时，不提供 20:00 之后的时段 |
| 约会结束 1 小时后 | 开放反馈，72 小时后关闭 |

演示环境用「演示时钟」：后台触发匹配时，把发布时间设为当前时刻，各个截止时间照常显示，但不会自动过期；推进阶段靠演示控制面板。

### 6.2 状态机

`MatchStage`（`web/src/api/types.ts`）的流转如下，状态定义与 `docs/技术方案.md` §3 对齐。

1. **等待**（waiting）→ 周三 19:00 → **已揭晓**（revealed）；没配上的进入**空周**（emptyWeek）。
2. 已揭晓 → 拒绝 → **已拒绝**（declined），本周结束。已揭晓 → 接受并提交时段 → **等对方**（awaitingPartner）。截止前没有回应 → `/match/expire`。
3. 双方都接受 → 系统取双方时段交集中最早、且距离现在至少 24 小时的那个 → 双方确认 → **已确认**（confirmed）。没有交集时，双方各有一次机会在周五 20:00 前补充时段，仍然没有交集就是「未约成」，不算任何一方的责任。一方到截止时间没有确认，本周没约成，未确认的一方记一次「未回应」（v1 §4.5）。
4. 约会开始前 2 小时 → **约会当天**（dateDay）→ 签到 → **已签到**（checkedIn）。
5. 约会结束 1 小时后 → **反馈**（feedback）→ 提交 → **等对方反馈**（awaitingFeedback）。
6. 双方都选「想再见」→ **互相想见**（mutual），揭晓微信 → 最终**关闭**（closed）。任何一方没选「想」，只显示「这次就到这里」，不告诉对方是谁没选。
7. 任意阶段举报 → **已举报**（reported），立即停止这一对后续的所有动作。

需要新增两个状态：**暂停本周**和**处罚中**。目前代码里没有。

### 6.3 选时段与确认

选「去」后进入时段网格：5 天 × 3 个时段，共 15 格，可以多选（v1 §4.1、§4.4）。目前的代码只给 3 个建议时段（`time.ts` 的 `proposedSlots`），是过渡做法，以本节为准；是否保留简化版见决策项。

### 6.4 约会当天

页面在开始前 2 小时变为可用，内容沿用 v1 §4.6：

- 对方照片、地点（可以复制地址或打开地图）、时间和倒计时。
- 状态按钮「我到了」「我会晚 10 分钟」「我穿了 ___」（限 20 字，过文本审核），每点一次给对方发一条站内状态。「我到了」同时算签到。
- 「临时取消」：开始前 6 小时以上取消算提前取消，不记责任；6 小时以内算迟取消。
- 安全提示：公共场所、不转账、不去宿舍或私密场所；「复制行程发给朋友」按钮；紧急情况拨打 110，并写明平台不能实时响应（v1 §4.9）。

见面前不交换联系方式，也不开放自由聊天。

### 6.5 反馈与交换微信

反馈表沿用 v1 §4.7：

1. 见到了吗：「见到了」「对方没来」「我没去」。
2. 见到了的话，再填：
   - 想再见吗：「想」「不想」「不确定」。
   - 聊得怎么样：1 到 5 分。
   - 匹配理由准不准，可以标出不准的那一条。
   - 不想再见的原因，可多选，不转给对方。
   - 见面时是否感到安全；选「否」直接进入举报流程。

选「想」时出现输入框：「留下你的微信号，只有你们都想再见时才会给对方」。双方都选「想」后，各自看到对方的微信号；微信号不会出现在其他任何地方。

v1 列的是「微信号或手机号二选一」，入驻时填写；v2 按已定决策只交换微信，并改为在反馈时填写，因为 Ditto 的问卷里没有这一题，放进去会破坏 1:1 的页序。爽约判定沿用 v1 §4.7 的对照表：例如 A 说「对方没来」、B 说「我没去」，判 B 爽约；A 说「对方没来」、B 72 小时内不反馈，也判 B 爽约；说法互相矛盾的记为争议，不处罚。

当前 `Feedback` 类型（`met、rating、again、comment、feltSafe`）需要补上「理由纠错」「不想再见的原因」「微信号」三个字段。

### 6.6 处罚（沿用 v1 §4.8）

| 行为 | 处理 |
|---|---|
| 爽约（按 v1 §4.7 的判定表） | 第 1 次警告并暂停 1 周；第 2 次暂停 4 周；第 3 次停止匹配，可以申诉。每学期清零 |
| 迟取消（距开始不足 6 小时） | 2 次折算 1 次爽约 |
| 周四 22:00 前不回应 | 记一次「未回应」；连续 2 周未回应自动暂停参与，用户回来点一下即可恢复（v1 §4.4） |

生病、考试冲突等理由走申诉。被处罚的一方在首页看到「处罚中」卡片，上面有原因、结束日期和申诉入口（v1 §4.3）。申诉由没有参与原决定的人复核，3 个工作日内确认收到，7 个工作日内给出书面决定（v1 §4.9）。这些档位都是 v1 的建议值，仍待确认（v1 §10 第 8 项）。

### 6.7 举报与屏蔽

- **举报**：海报、约会当天页、反馈页都有入口。分类沿用 v1 §4.9（与 `REPORT_CATEGORIES` 一致）：骚扰或威胁；诈骗迹象；照片或身份不符；线下不当行为；疑似未满 18 周岁；其他。一提交，双方永久不再配对，正在进行的匹配立即终止。诈骗、人身安全、疑似未成年这三类，被举报人立即暂停匹配，等人工复核。人工处理时效：这三类 24 小时内，其他 72 小时内（v1 建议值）。涉诈线索按反诈法流程向公安报送（v1 §4.9）。
- **屏蔽名单**：用户填对方的名字、手机号或邮箱（13 §6）。只要手机号或邮箱能对上，就永不配对，被屏蔽的人不会收到任何通知。
- **拒绝时屏蔽**：拒绝时可以勾选「不再匹配此人」。

## 7. 运营后台（`/admin`）

后台是演示的一部分，也是以后真实运营台的雏形。它需要后端：目前的部署只是 nginx 托管静态页面（`deploy/`），前端数据存在浏览器的 localStorage 里。后端接入点已经写在 `web/src/api/index.ts` 的 `TODO(spring-boot)` 注释里。

### 7.1 访问

后台用独立的管理员账号和密码（环境变量配置），不和演示用户共用登录。所有操作写审计日志。

### 7.2 功能

| 功能 | 说明 |
|---|---|
| 立即触发本周匹配 | 一个按钮完成「锁定名单 → 硬过滤与打分 → 求解 → 雷区复核 → 生成理由和方案 → 发布」。完成后显示参与人数、配上几对、空周人数、模型调用次数和降级次数。同一周重复触发不会重新配，必须先「重置本周」 |
| 合成用户 | 约 200 个，用固定随机种子生成，可以重新生成。性别、想认识的性别、学校、年级、兴趣按预设比例分布，保证每个演示账号至少有 3 个能通过硬过滤的候选人。头像一律用插画或纯色占位，**不用任何真人照片** |

## 10. 验收标准

验收的核心是**用同一份录屏脚本跑我们和 Ditto，逐页对照**。Ditto 那一侧的素材已经在 `docs/research/assets/` 里，我们这一侧用脚本自动截图。

### 10.1 首页开场

- **方法**：用 06 抓 Ditto 时的同一套时间点（`ditto-hero/mobile-t*.png`）截我们的首页，逐帧对照。
- **通过条件**：
  - 标题错峰节奏、手机上滑、信鸽入场的时间点与 06 的记录相差不超过 100ms；视差速度符合动效需求文档里的公式。
  - 打开系统「减少动态效果」时，直接显示最终画面。
  - 弱网下标题先出来，不等图片。

### 10.2 入驻问卷

- **方法**：
  - `web/scripts/walk.mjs` 按 Ditto pass3 录屏（12 §1）预填同样的草稿，每页进入 2.6 秒后截图。
  - `web/scripts/compare.sh` 把我们的截图和 `pass3/<场景>/NN-a.png` 左右拼在一起。
  - 目前覆盖 S1、N1，需要补齐 S2、S3、N2、N3。
- **英文对照（`?lang=en`）的通过条件**：
  - 页序与 12 §1 的表格完全一致。
  - 每页进度条填充与 12 §1 的记录相差不超过 2px。
  - 选项胶囊、气泡、按钮的位置和颜色一致。
  - 转场节奏符合 12 §4 的参数。
- **中文（`?lang=zh`）的通过条件**：
  - 跑同一份脚本，§2.3 隐藏的 8 题不出现，进度条分母按 §4.1 重新计算。
  - 页面上不残留英文。
  - 学校邮箱、单位、货币、来源选项都已本地化。
  - 未满 18 岁的生日无法继续。

### 10.3 登录后页面

- **方法**：每个路由在 390×844 下截图，和 `ditto-app/logged-in/*.png`、`profile-edit/`、`profile-edit-2/` 对照。

  - 每一段 AI 文字都有标签。

## 11. 待用户决策项

### 11.1 v2 新增

1. **非学生路径上线后是否保留？** 演示保留是为了 1:1 对照；v1 只服务在校生。如果保留，需要另外设计非学生池和身份核验。
2. **吉祥物**：原创形象由谁设计、什么时间交付、往什么方向做（关卡 17）。
3. **品牌名和域名**：「见一面」是否定稿；aiditto.cn 含「ditto」，是否另外注册域名（关卡 29）。
4. **演示站访问口令**：备案下来之前，是否给演示站加访问口令（§8.1）。
5. **首页统计数字和证言**：演示期是照常显示并标注「占位」，还是直接隐藏。
6. **演示数据里的真实校名**：`mock.ts` 和首页证言用了北大、清华、人大、复旦等，是否改成「示例大学」这类虚构名称，以免被理解为合作关系【推断】。
7. **邀请抽屉的承诺**：「邀请好友锁定下周匹配」是否保留；保留就要在算法里实现优先匹配。
8. **时段选择**：按 v1 用 15 格网格，还是保留现在代码里的 3 个建议时段（更快，但和 v1 不一致）。
9. **本地兴趣**：是否在 8 个兴趣之外增加本地兴趣胶囊（例如桌游、剧本杀、追星）；如果加，只作为普通胶囊，不加分支。
10. **编辑页的兴趣分支规则**：Ditto 的规则未知（09 §10.3），我们暂时按题库顺序取前 3 个，是否接受。
11. **雷区复核**：是否允许大模型否决配对（§5.2 第 5 步）。不允许的话，雷区文字只用来写理由。
12. **LongCat**：备案和价格都没有调研，是否接受「先演示、上线前再核」（关卡 26）。
