# PRD：校园 AI 红娘（中国版 Ditto）MVP

- 状态：待用户评审。评审通过前不开发。
- 日期：2026-11-12
- 输入：`docs/research/01-ditto-产品拆解.md`、`02-国内竞品与市场.md`、`03-合规与学生认证.md`、`04-技术选型.md`。下文用「01 §4.3」指第 01 份调研的第 4.3 节。
- 证据标签沿用调研：【已证实】【推断】【猜测】。没有标签的句子是本 PRD 的产品决定，不是事实断言。
- 产品名未定，下文称「本产品」。

## 1. 定位与目标用户

**一句话。** 每周三给本校在读的你介绍一位同学，并替你们定好第一次校园见面的时间和地点。见完面你说感受，下一次介绍据此调整。

**目标用户。** 试点学校年满 18 周岁的在读本科生和研究生，持有该校学生邮箱（edu.cn），愿意每周花 1 小时见一个新的人。

不服务的人：未满 18 周岁的学生、教职工、校友、外校人员。Ditto 条款把教职工写进了可用人群，这是要避免的风险【已证实】（01 §6.1）。

**为什么是「定好见面」。** 中国大学生社交以线下或线上线下并重为主，纯线上约 17%【已证实】（02 §4.1，中青校媒 2,634 份问卷）。时间被学业和就业挤占，约四分之一既没谈过也不想谈【已证实】（02 §4.1，首经贸 32,282 份问卷）。所以本产品替用户省掉的是「约」的成本，不是「找」的成本。

## 2. 差异化

国内已有一批「edu 邮箱 + 深度问卷 + 每周推一人」的产品。CampusDate（上交学生团队，2026-03-10 上线）、FDU Date（复旦）、TP Date（清北）、Soulink、哈啰 Match 都属于这一类【已证实】（02 §2.1）。按公开材料，它们都停在交换微信或联系方式，见面由用户自己约【已证实】（02 §3.4 对照表）。

本产品在交换联系方式之前多做三件事：

1. 系统根据双方勾选的空闲时段，定出时间和本校公共地点。
2. 见面前双方都要确认一次时间，见面当天有到达和取消状态。
3. 见面后收结构化反馈，反馈进入下一周的匹配，并决定是否交换联系方式。

MatchUs 创始人自称，匹配成功者里约 6% 成为稳定情侣，并说用户在问卷里填的是「希望成为的自己」【已证实】（02 §2.1，中青报 2026-07-21，当事方口径）。这说明问卷本身预测不了见面结果。见面反馈才是我们和问卷类竞品拉开差距的数据【推断】（02 §6.1）。

上交、复旦已经有每周揭晓的仪式【已证实】（02 §2.1）。如果只复制问卷和周三推送，在这些学校会被看成仿盘【推断】（02 §6.2）。试点因此避开这些学校，见第 7 节。

## 3. MVP 范围

### 3.1 核心闭环

```
入驻问卷 → 每周三匹配 → 约会方案卡片 → 双方确认时间 → 见面后反馈
                ↑                                              │
                └──────────── 反馈进入下周匹配 ─────────────────┘
```

每个 MVP 功能都必须服务这条闭环中的某一步，或是合规硬性要求。

### 3.2 做

| 功能 | 服务哪一步 |
|---|---|
| 手机号注册、学校邮箱验证、年龄门、同意书 | 入驻（合规前置） |
| 分段问卷，3 道开放题，AI 抽取画像后由用户确认 | 入驻 |
| 每周参与开关（默认参与，可暂停本周） | 匹配 |
| 每周三 19:00 发布匹配卡片，附 AI 写的匹配理由 | 方案卡片 |
| 「去 / 不去」与勾选空闲时段合并成一次提交 | 确认时间 |
| 系统求时段交集，从地点库选地点，双方各确认一次 | 确认时间 |
| 见面页：到达、晚到、取消、复制行程给朋友 | 见面 |
| 见面后反馈；双方都想再见才互相显示联系方式 | 反馈 |
| 举报、拉黑、爽约处罚、申诉 | 闭环里每一步的安全兜底 |
| 关闭个性化匹配、删除画像标签、注销 | 合规（算法推荐规定第十七条） |
| 通知短信（周三发布、待确认、反馈提醒） | 把人叫回闭环 |
| 最小运营后台：审核队列、举报处理、批次监控 | 安全兜底 |

### 3.3 不做

下面这些在 MVP 里明确不做。理由一栏说明为什么它不服务闭环，或为什么风险大于收益。

| 不做 | 理由 |
|---|---|
| 站内聊天、私信、群聊 | 会触发即时通讯实名和内容审核，也会让产品退回「加微信后就卸载」【推断】（03 §5.2、02 §5.1） |
| 广场、动态、公开主页 | 校园社区反复死于关系迁移到微信【已证实】（02 §5.1）。还会被认定为有「舆论属性」【推断】（03 §2.3） |
| AI 对话式问卷 | Ditto 用户抱怨 AI 问个没完【已证实】（01 §3.2，Her Campus）。改用有进度条的表单 |
| 把照片交给大模型分析 | 不打颜值分最可靠的做法是模型根本看不到照片。照片只走内容审核 API |
| 人脸核验、活体检测、证件 OCR | 人脸是生物识别敏感信息，且不得作为唯一验证方式【已证实】（03 §4.4） |
| 采集性取向、宗教、政治、民族、GPS | 属于或接近敏感个人信息【已证实】（03 §4.1）。替代做法见第 6.1 节 |
| 收费、小费、会员、活动票 | 收费会触发增值电信经营许可，跨省需 1000 万元注册资本【已证实】（03 §1.3） |
| 推荐奖励、邀请返现 | 涉及结算。冷启动用渠道参数归因即可 |
| 多校、跨校、城市模式、暑假模式 | 单校先验证两侧密度【推断】（01 §7.1） |
| 学信网验证 | 扩校阶段备选，见第 6.2 节 |
| App、小程序、Web Push | 已定独立 H5。iOS Web Push 要求先添加到主屏幕【已证实】（04 §1.1） |
| 文生图海报、AI 头像 | 有肖像和深度合成风险，生成图片还可能抬高备案档位【推断】（03 §2.3、04 §4.1） |
| 线下派对、联谊、包场 | 会把平台推向「群众性活动组织者」【推断】（03 §6.1） |
| 朋友模式、搭子模式 | 先把一种关系意图跑通 |
| 第二次约会的安排 | 双方互相显示联系方式后，由他们自己安排 |

## 4. 用户故事、页面与状态

### 4.1 每周时间表（Asia/Shanghai）

| 时间 | 事件 |
|---|---|
| 周二 23:59 | 本周参与名单锁定。之后改问卷，算进下周 |
| 周三 19:00 | 匹配卡片发布，发通知短信 |
| 周四 22:00 | 「去 / 不去」与时段的回应截止 |
| 双方都选「去」的当下 | 系统求交集，发时间方案 |
| 方案发出后 12 小时内，且不晚于见面前 12 小时 | 双方确认截止 |
| 周五至下周二 | 见面时段：每天 12:00、15:30、18:30 三档，每档 1 小时。不提供 20:00 之后的时段 |
| 见面结束 1 小时后 | 反馈开放，发提醒短信。72 小时后关闭 |

Ditto 的周二截止、周三 19:00 发布没有公开时区【已证实】（01 §12）。本产品把时区写死成北京时间。见面窗口在下一次周三之前结束，所以一个人不会同时有两场待办约会。

### 4.2 入驻

**用户故事。** 作为在读学生，我想在 10 分钟内说清楚我是谁、想认识什么样的人，并能看到系统从我的回答里读出了什么。

**页面顺序：**

1. 落地页：一段话说明每周三介绍一位同学、系统定见面、见面前不聊天。写明「匹配和理由由 AI 辅助生成」。
2. 手机号与短信验证码。
3. 学校邮箱验证码。只接受试点学校学生邮箱的域名白名单，教职工域名拒绝。
4. 生日、性别、年级，以及「是否年满 18 周岁」声明。未满 18 周岁直接结束流程，见第 6.3 节。
5. 同意页：用户协议、隐私政策、算法推荐说明各自单独勾选。「想认识的性别」单独一页同意，见第 6.1 节。
6. 问卷，分 4 段，每段显示进度，可保存后继续：
   - 关于我：作息、兴趣标签、周末怎么过。
   - 我在找什么：关系意图（「认真认识，看能否恋爱」或「先见一面看看」）、年级窗口、明确不接受的项（如吸烟）。
   - 价值观：约 20 道李克特量表题。题目来自中国学生的说法，不翻译美国校园黑话【推断】（01 §11 需要改造 5）。
   - 匹配松紧：「宁缺毋滥」或「愿意试试」，决定匹配分数门槛。来源是 Ditto 的四档设计，这里简化成两档【已证实】（01 §3.1）。
7. 3 道开放题，例如「一个理想的周六下午」。
8. 照片：1 到 3 张，至少 1 张清晰正脸。上传后走内容审核。
9. 预留联系方式：微信号或手机号，选一个。只在双方见面后都想再见时显示给对方。
10. 画像确认页：展示 AI 从开放题里抽出的标签，每个标签带原文出处。用户可以删除或改写任一标签。

**状态：** `未注册 → 已验证手机 → 已验证邮箱 → 问卷进行中 → 待审核 → 合格`。照片或文本审核不通过时进入 `需修改`，用户改完回到 `待审核`。

**异常：**

- 邮箱验证码收不到：页面提示查垃圾箱和隔离区。多校承认会拦截外部邮件【已证实】（03 §7.2）。可重发，10 分钟有效。
- 邮箱域名不在白名单：显示「本产品目前只在 X 大学试点」，并允许留手机号排队。
- 问卷中途退出：保留进度，24 小时后发一次短信提醒，只发一次。

### 4.3 每周三匹配

**用户故事。** 作为合格用户，我想每周三晚上知道这周有没有人，以及为什么是这个人。

首页根据本周状态显示一张卡片：

| 本周状态 | 首页显示 |
|---|---|
| 已暂停本周 | 「本周已暂停」，可恢复（周二 23:59 前） |
| 等待周三 | 倒计时，本周参与开关 |
| 有匹配 | 约会方案卡片 |
| 空周 | 「本周没有足够合适的人，你自动进入下周」 |
| 处罚中 | 处罚原因、结束日期、申诉入口 |

**空周。** 系统宁可不配，也不把低于分数门槛的人凑成一对【推断】（04 §3.2）。Ditto 用户抱怨的不是空周本身，而是空周和随机感同时出现【已证实】（01 §9.3）。空周文案不暗示用户哪里不够好，也不显示本校参与人数。

### 4.4 约会方案卡片

**用户故事。** 作为收到匹配的人，我想看到对方是谁、为什么推荐 TA、我们会在哪里见面，再决定去不去。

卡片内容：

- 对方昵称、年级、学科大类。不显示真实姓名和具体学院，因为校内熟人多。心动人大的组织者把「容易碰到熟人」写成了产品约束，只给最基本的信息【已证实】（02 §2.2）。
- 对方照片，叠加查看者编号水印。
- 「为什么是你们」，2 到 3 条。每条必须指向双方都填过的具体回答，带「AI 生成」标识。每条旁边有「这条不对」按钮。Ditto 的理由被学生说成空泛，这是信任事故【已证实】（01 §9.1）。
- 拟定地点：从本校地点库里选一个，并写明活动，例如「一杯饮品，约 45 分钟」。时间在下一步定。
- 两条见面开场提示，同样带 AI 标识。
- 两个按钮：「去，并勾选我的空闲时段」和「这次不去」。
- 举报入口。

**拒绝。** 选「不去」时，用户可以多选原因，也可以写一句话。原因只进入模型和运营统计，不转发给对方。对方看到的是「这次没有约成，你自动进入下周」。这对人以后不再配对。

**无回应。** 周四 22:00 前任一方没回应，匹配进入 `过期`。没回应的一方本周记一次「未回应」，连续 2 周未回应自动暂停参与，用户回来点一下即可恢复。

### 4.5 双方确认时间

**用户故事。** 作为双方都愿意去的人，我不想来回商量时间，系统应该直接给我一个能去的时间。

1. 双方都选「去」后，系统在双方时段的交集里选最早一个，且距现在至少 24 小时。
2. 双方各收到时间方案：日期、时段、地点、地图说明。
3. 双方都点「确认」后，状态变为 `已确认`。

**没有交集。** 双方各有一次机会在周五 20:00 前补充时段。补充后仍没有交集，状态为 `未约成`，不计任何人的责任。

**一方未确认。** 到截止时间仍未确认，状态为 `未确认`。已确认的一方收到「对方没能确认，本周没有约成」。未确认方记一次「未回应」。

### 4.6 见面

见面页在开始前 2 小时变为可用：

- 对方照片、地点、时间。
- 状态按钮：「我到了」「我会晚 10 分钟」「我穿了 ___」（限 20 字，过文本审核）。每次点按会给对方发一条站内状态和一条短信。
- 「临时取消」：开始前 6 小时以上取消算「提前取消」，不记责任；6 小时以内取消算「迟取消」。
- 安全提示：公共场所、不转账、不去宿舍或私密场所。「复制行程发给朋友」按钮会复制一段文字，内容是时间、地点和对方昵称。

见面前不交换联系方式，也不开放自由聊天。状态按钮只有固定选项和一个短文本，所以它不是即时通讯【推断】（03 §5.2，需律师确认）。

### 4.7 见面后反馈

**用户故事。** 作为见过面的人，我想用 1 分钟说清楚这次怎么样，并且只有在双方都愿意时才交换联系方式。

反馈表：

1. 见到了吗：「见到了」「对方没来」「我没去」。
2. 见到了的话：
   - 想再见吗：「想」「不想」「不确定」。
   - 聊得怎么样：1 到 5 分。
   - 匹配理由准不准，可以标出不准的那一条。
   - 不想再见的原因，可多选。原因不转发给对方。
   - 见面时你感到安全吗。选「否」直接进入举报流程。
3. 双方都选「想」：互相显示预留的联系方式。其他组合只显示「这次没有双向」，不说明是谁不想。

**爽约判定：**

| 双方反馈 | 结果 |
|---|---|
| A 说「对方没来」，B 说「我没去」 | B 爽约 |
| A 说「对方没来」，B 说「见到了」或「对方没来」 | 争议，不处罚任何一方，记录。同一人 3 次争议转人工 |
| A 说「对方没来」，B 72 小时内不反馈 | B 爽约 |

### 4.8 处罚档位

爽约档位（每学期清零）：第 1 次警告并暂停 1 周；第 2 次暂停 4 周；第 3 次停止匹配，可申诉。2 次迟取消折算 1 次爽约。生病、考试冲突等理由走申诉。Ditto 只写了「临时取消不通知会被 ban」，没有档位和申诉路径【已证实】（01 §6.3），这是我们要补上的。

### 4.9 举报

每张匹配卡片、见面页、反馈页都有举报入口。分类：骚扰或威胁；索要钱财、推销、投资或其他诈骗迹象；照片或身份不符；线下不当行为；疑似未满 18 周岁；其他。

- 举报一提交，举报人和被举报人永久不再配对，正在进行的匹配直接终止。
- 诈骗、人身安全、疑似未成年三类，被举报人立即暂停匹配，等待人工复核。
- 人工处理时效：上面三类 24 小时内，其他 72 小时内。数字是建议值，待确认。
- 申诉由没有参与原决定的人复核，3 个工作日内确认收到，7 个工作日内给出书面决定。这段照抄 Ditto 的申诉页【已证实】（01 §6.3）。Ditto 只用邮箱收举报，学生找不到入口【已证实】（01 §11 需要改造 10），我们放在页面里。
- 紧急情况页面提示拨打 110，并写明平台不能实时响应。
- 涉诈线索按反诈法流程向公安报送【已证实】（03 §6.3）。

### 4.10 设置

- 暂停本周、恢复参与。
- 关闭个性化匹配：关闭后立即停止匹配，账号和安全记录保留，可随时重新打开。规定要求提供关闭开关，或不针对个人特征的选项【已证实】（03 §3）。本产品不提供「随机匹配」作为替代，因为随机约见陌生人有安全风险。
- 查看和删除画像标签。
- 修改问卷、照片、预留联系方式。
- 注销：删除画像、照片和联系方式。举报和处罚记录按法定期限保留。
- 算法说明页：说明匹配使用了哪几类信息、不使用照片和外貌、理由由哪个模型生成，并公示模型名称和备案号【已证实】（04 §2，网信办 2026-05-13 公告）。

## 5. 约会地点库

运营在试点学校实地选 8 到 15 个点：校内咖啡、奶茶店、食堂公共区、图书馆周边。每个点记录开放时间、适合的时段、室内或室外。中国校园的默认约会场所不是咖啡馆，地点库要按学校重做【推断】（01 §11 需要改造 4）。原则沿用 Ditto：公共、短、低消费、有第三者在场【已证实】（01 §5.2）。

地点由系统按规则从地点库挑选，规则是双方偏好的活动类型加上该时段营业。大模型不选地点，也不编造地点。平台不订座、不包场、不派人到场。文案写「系统建议的公共地点」，不写「平台安排的约会」【推断】（03 §6.1）。

## 6. 安全与隐私

### 6.1 不采集性取向，照样能匹配

匹配只需要回答「两个人是否互相在对方想认识的范围里」。本产品不问「你的性取向是什么」，只问两件事：

- 我的性别：男、女。
- 我想认识的人：男、女、都可以（可多选）。

两人之间有边的条件是：A 的性别在 B 的范围里，且 B 的性别在 A 的范围里。这样异性、同性、都可以的用户都能匹配，系统里不存在取向标签。

「想认识的性别」字段仍然可能推断出取向。性取向在 GB/T 45574-2025 附录 A 里列为敏感个人信息【已证实】（03 §4.1）。所以这个字段按敏感信息处理：

- 单独一页同意，用户不同意就不能完成注册。
- 加密存储，只给匹配求解器读。
- 不进入任何大模型提示词，不显示给任何用户，不进入匹配理由。
- 运营后台默认不可见。

它算不算敏感信息，要请律师确认【推断】（03 §10 第 6 项）。我们先按敏感信息处理，这样无论律师结论如何都不用返工。

其他不采集的：宗教、政治、民族、收入、精准定位、身份证照片。性格题避开心理健康和性生活方向。测评若输出「抑郁倾向」一类标签，会靠近医疗健康信息【推断】（03 §4.1）。

### 6.2 学生认证：edu.cn 与合规调研的冲突

**冲突。** 合规调研认为 edu.cn 不能当全国唯一的学生身份门。理由是高职邮箱覆盖分化大、校外邮件会被拦截、毕业后邮箱被回收（45 天到 1 年不等），而且邮箱不是反诈法意义上的真实身份信息【已证实】（03 §8.2、§8.3）。调研建议的方案是手机号实名加学信网学籍验证报告（03 §8.5）。用户已决定用 edu.cn 邮箱。

**本 PRD 的做法：**

1. MVP 只开一所学校，按用户决定用该校学生邮箱证明在读身份。试点学校必须邮箱制度完善，见第 7 节。
2. 手机号同时必填。手机号承担两件事：账号的真实身份信息，以及周三通知。《互联网用户账号信息管理规定》第九条列举的方式是手机号、证件号、统一社会信用代码，不包括邮箱【已证实】（04 §5.2）。
3. 每学期初要求重新验证一次邮箱。验证不了就暂停参与，防止毕业生留在池子里【推断】（03 §8.3）。
4. 学信网学籍在线验证报告写成扩校阶段的备选。它覆盖高职和普通本科，不依赖学校发不发邮箱【已证实】（03 §8.4）。

**取舍。** 单校试点里，邮箱制度完善的学校能让 edu.cn 覆盖绝大多数在读生。代价是扩到第二所学校时，可能要换认证方式。手机号从第一天就必填，所以换方式只是加一个学生身份证明，不用重做账号体系。这一项列为待用户确认。

### 6.3 拒绝未成年人

大一存在未满 18 周岁的学生【已证实】（03 §4.3）。约会加线下见面不适合做未成年人模式，所以只向年满 18 周岁的人提供服务。

MVP 做法：注册时填生日，加一句年满 18 周岁声明。未满 18 周岁不能注册，生日一年内不能修改。疑似未成年的举报会立即暂停该账号。声明能不能满足监管要求，需律师确认（03 §10 第 7 项）。如果不能，加阿里云金融级实人认证，1 元/次【已证实单价】（04 §5.2）。这一项列为待决策。

### 6.4 AI 生成标识

《人工智能生成合成内容标识办法》2025-09-01 起施行，要求在文本旁边或界面上给出显著提示，并在用户协议里写明标识方式【已证实】（03 §2.4）。

本产品里 AI 生成的文本只有三类：画像标签、匹配理由、开场提示。每一处都带「AI 生成」角标，点开说明生成方式。落地页和用户协议也写明。Ditto 有用户用了一段时间才知道背后是 AI【已证实】（01 §9.1），我们在第一页就说明。

### 6.5 其他

- 照片只给本周的匹配对象看，而且只在卡片发布之后。不存在可浏览的主页。只给一位匹配对象看是否构成「公开」，需律师确认【推断】（03 §4.1）。
- 用户协议禁止保存、转发、公开对方的照片和信息。
- 大模型只用境内已备案模型，数据不出境【推断】（03 §4.5）。与模型厂商的合同写明不得用学生数据训练模型。
- 简介、昵称、开放题、状态短文本里的手机号、微信号、二维码、外链，审核命中就打回【推断】（04 §5.3）。
- 首次匹配前展示一次反诈提示：不转账、不投资、不在见面前谈钱。

## 7. 试点学校与冷启动

### 7.1 选校标准

按排除法选，不按排名选【推断】（02 §6.3）。

先排除已有周更匹配品牌或学生组织品牌的学校：上海交大、复旦、同济、华东师范、上财（CampusDate、FDU Date），浙大（MatchUs），清华、北大（TP Date、Soulink），人大（心动人大）【已证实】（02 §6.3）。城市上优先避开上海和杭州【推断】（02 §6.3）。

再逐条核查：

1. 学生邮箱入学自动开通，或全体学生可开通。例如中国矿业大学的学生邮箱随学号自动开通，毕业后保留一年【已证实】（03 §8.2）。这只说明它满足这一条，不等于推荐它。
2. 用目标学校真实学生邮箱做收信测试，验证码能在 1 分钟内进收件箱。
3. 单一主校区，步行可达至少 8 个公共见面点。
4. 综合类大学。注册开放后第一周公开看两侧人数，失衡超过团队能接受的范围就停，换学校，不用算法硬配【推断】（02 §6.3）。
5. 学生会、研会没有把恋爱匹配做成自己的品牌。
6. 有活跃的校内论坛或课程群，可以发一次帖子测需求。
7. 团队里至少有一名在校学生或校友，能实地核对地点库并处理当地问题。

### 7.2 冷启动

1. 等候名单阶段：落地页开放注册和问卷，不发匹配。页面显示「X 大学：满足条件后的第一个周三开始」。
2. 首批开放门槛：本周参与者中，每个匹配方向（例如「男找女」和「女找男」）各至少 100 人。理由是试点想要每周几十对，而发布、接受、确认、出席每一步都有流失【推断】。具体数字待用户决定。
3. 渠道：校内论坛一次帖子、课程群转发、少量校园大使。参考 MatchUs 在 CC98 的起步方式【已证实】（02 §2.1）。不买表白墙广告，因为那些墙常有冒名和广告问题【已证实】（02 §2.3）。不用标题党海报，Ditto 的这类海报被学生当成诈骗【已证实】（01 §7.4）。
4. 链接带渠道参数，只做归因，不发奖励。
5. 文案用「本校交友」的名义，允许「见一面、不合适就停」。约 25% 学生没有恋爱意愿【已证实】（02 §4.1），只写「脱单」会劝退谨慎的人【推断】（02 §6.1）。

## 8. 成功指标

所有比率都写死分子和分母。Ditto 的 20%、65%、69%、「超过一半用户」分母各不相同，已经互相矛盾【已证实】（01 §8.1）。我们不对外公布任何「成功率」。

**北极星指标：周见面数。** 定义是本周双方都反馈「见到了」的匹配数。

| 指标 | 分子 | 分母 |
|---|---|---|
| 入驻完成率 | 进入「合格」状态的用户 | 完成邮箱验证的用户 |
| 周参与率 | 本周参与的合格用户 | 本周所有合格且未处罚的用户 |
| 匹配覆盖率（1 减去它就是空周率） | 本周拿到匹配的人 | 本周参与的人 |
| 双方接受率 | 双方都选「去」的匹配 | 本周发布的匹配 |
| 约定率 | 进入「已确认」的匹配 | 双方都选「去」的匹配 |
| 出席率 | 双方都反馈「见到了」的匹配 | 「已确认」的匹配 |
| 端到端见面率 | 双方都反馈「见到了」的匹配 | 本周发布的匹配 |
| 再见意愿率 | 双方都选「想再见」的匹配 | 双方都反馈「见到了」的匹配 |
| 爽约率 | 判定为爽约的人次 | 「已确认」匹配涉及的人次 |
| 反馈提交率 | 提交反馈的人次 | 「已确认」匹配涉及的人次 |
| 理由纠错率 | 被标「这条不对」的理由条数 | 展示过的理由条数 |
| 安全举报率 | 安全类举报数 | 每 100 个发布的匹配 |
| 举报处理达标率 | 在时效内处理完的举报 | 所有举报 |

端到端见面率可以参考 Ditto 重复最多次的自报口径：匹配里约 20% 变成见面【已证实，公司自报】（01 §8.1）。它没有独立审计，只能当参照，不能当行业基准。

M2 转 M3 的建议门槛（待用户决定，均为【猜测】，没有可靠基准）：连续 4 周端到端见面率不低于 20%；爽约率不高于 10%；安全举报全部在时效内处理；没有未成年人进入匹配。

## 10. 待用户决策项

1. **认证组合。** 按你的决定，MVP 用 edu.cn 邮箱，手机号同时必填，学信网写成扩校备选。是否确认这一取舍（第 6.2 节）？
2. **试点学校。** 按第 7.1 节核查后由你拍板。调研不足以现在指定校名。
3. **年龄核验强度。** 默认用生日加声明。如果律师认为不够，是否接受实人认证（1 元/次，涉及人脸）？
4. **「想认识的性别」与同性匹配。** 默认支持男、女、都可以，按敏感信息处理并单独同意。是否接受？
5. **见面前是否交换联系方式。** 默认不交换，只有到达状态按钮，见面后双方都想再见才显示联系方式。Ditto 是在确认时间后交换电话【已证实】（01 §4.3）。
6. **是否收身高。** 默认不收。据虎嗅报道，复旦早期的人工月老会看身高（02 §5.3）。协调人未能核对这篇虎嗅文章，所以这里不加证据标签。收身高会加重外貌筛选。
7. **首批开放门槛。** 默认每个匹配方向至少 100 名本周参与者。
8. **处罚档位与举报时效。** 默认值见第 4.8、4.9 节。
9. **研究生是否进同一个池。** 默认本科生和研究生同池，靠年级窗口过滤。
10. **产品名与公司注册地。** 注册地会影响网信办的口径。
11. **M2 转 M3 门槛。** 第 8 节的数字是猜测，需要你定。
